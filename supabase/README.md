# supabase/ — бэкенд (слой L5)

Файлы бэкенда «Библиотеки Таухид»: аккаунты, приватные/платные книги, подписки.
Проектное обоснование и модель — в `../BACKEND.md`.

| Файл | Что |
|---|---|
| `schema.sql` | Миграция: таблицы, RLS-политики, приватный Storage-бакет. Идемпотентно. |
| `config.js` | Публичные параметры проекта (URL + publishable-ключ). Коммитить можно — не секрет. |
| `client.js` | Тонкий клиент на голом `fetch` (auth/rest/storage) → `window.SB`. Подключён в `index.html`. |

## Настройка (делает автор в своём аккаунте Supabase)

1. **Создать проект** на [supabase.com](https://supabase.com) (free-тариф).
2. **SQL Editor → выполнить `schema.sql`** (вставить целиком → Run).
3. **Authentication → Providers → Email:** включить; **выключить публичную регистрацию**
   («Allow new users to sign up» = off) — регистрация закрытая (только владелец).
4. **Authentication → URL Configuration:** прописать адрес приложения в **Site URL** и
   **Redirect URLs** (нужно для возврата магик-линка).
5. **Settings → API keys:** скопировать **Project URL** и **publishable-ключ**
   (`sb_publishable_…`) → вписать в `config.js`.
6. **Authentication → Users → Add user** — завести владельца по почте. Регистрации в
   приложении нет (`create_user:false`), аккаунты появляются только отсюда.
7. **Секретный ключ (`sb_secret_…`) никуда не коммитить.** Он нужен только локально для
   заливки приватных книг (`tools/upload-private.js`) и для Edge Functions (фаза 3) —
   задаётся через переменную окружения / секреты Supabase, не в репозитории.

Готово: фазы 0–2 (схема, аккаунты, приватное чтение). Дальше — подписки (фаза 3:
Edge Function + вебхук платёжки). Статусы — в таблице фаз `../BACKEND.md`.

## Заливка приватной книги

```bash
node tools/validate.js <папка-книги>          # CI её не проверит — только руками
SUPABASE_SERVICE_KEY=sb_secret_… node tools/upload-private.js <папка-книги> --owner <почта>
```

Идемпотентно: повторный запуск перезаливает файлы и обновляет запись — как переимпорт.

Безопасность: доступ решают RLS-политики в БД, а не приложение. Publishable-ключ —
публичный; секретный — только локально/на сервере. Подробности — `../BACKEND.md`.
