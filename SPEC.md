# SPEC v1 — Параллельная читалка Markdown-книг («Tawfiq al-Mannan reader»)

> Этот документ — **спецификация для реализации**, а не код. Код пишет Claude Code
> («Клудод»). Здесь зафиксированы контракт данных, модель, режимы, фазы и правила.
> Документ — источник истины: при расхождении кода и спеки правится либо код, либо
> (осознанно) спека, но не молча.

---

## 1. Что это

Веб-приложение для **параллельного чтения** книги в двух языках (оригинал + перевод),
выровненных по смысловым **секторам**. Первая книга — «Тауфик аль-маннан», т. 2
(арабский ↔ русский), но приложение — **обёртка над любой парой языков**: оно ничего не
знает о конкретной книге и работает с любым контентом, соблюдающим Контракт (раздел 3).

Две цели пользователя:
1. **Параллельное чтение** — оригинал и перевод рядом/чередуясь.
2. **Изучение языка** — видеть строку оригинала и сразу её перевод.

## 2. Стек и ограничения

- **Чистый vanilla JS + HTML + CSS.** Без фреймворков, без сборщиков. Один-два .js-файла.
- **Статический хостинг (Netlify).** Бэкенда в v1 нет.
- **GitHub-репозиторий**, разработка с разных устройств. Структура — обычный статический сайт.
- **Контент НЕ бандлится в код.** Лежит отдельными папками, грузится в рантайме через `fetch`.
- **Мобайл-фёрст.** Основной сценарий — телефон, вертикально. Альбомная/планшет — вторично.
- **НЕ использовать** `localStorage`/`sessionStorage`-зависимый функционал как критический
  (Netlify ок, но настройки храним в `localStorage` — это допустимо для статики; в артефактах
  Claude.ai это запрещено, но здесь обычный сайт, так что можно).
- Никаких готовых markdown-рендереров для тела: **парсер сносок/якорей пишется свой**
  (стандартные рендереры якоря-комментарии и сектора корректно не обработают). Допустимо
  использовать лёгкий markdown→HTML только для **inline-разметки внутри сектора** (жирный,
  курсив, кавычки), но разбиение на сектора/сноски/страницы — собственное.

## 3. КОНТРАКТ КНИГИ (ядро переиспользования)

Любая книга, чтобы открыться в приложении, обязана соблюдать следующее.

### 3.1 Структура папок
```
/books/<bookId>/
    ar/NN.md          # оригинал, по главам (NN — номер главы, напр. 07)
    ru/NN.md          # перевод, ТЕ ЖЕ имена файлов
    img/pNNN.jpg      # скан страницы; имя = номер страницы (см. 3.4). Опционально.
    book.json         # манифест книги (см. 3.5)
```
- Имена файлов глав в `ar/` и `ru/` **идентичны**.
- `img/` опциональна; если её нет — функция «показать скан» просто недоступна.

### 3.2 Сектор
Минимальная единица выравнивания. Обычно абзац или предложение.

- Каждый сектор предваряется якорем на **отдельной строке**:
  `<!-- s007 -->`
- Затем идёт текст сектора (может быть несколько строк до пустой строки).
- Сектора разделяются пустой строкой.
- Якорь `sNNN` — **уникален в пределах главы** и **совпадает** в `ar/NN.md` и `ru/NN.md`.
- Выравнивание пар идёт **по совпадению id**, НЕ по порядку.

> Почему HTML-комментарий: невидим в Obsidian-рендере (автор правит .md как обычный текст),
> тривиально парсится, отбрасывается при любом экспорте, не конфликтует с Markdown.

**Группы (1 оригинал ↔ несколько секторов перевода).** Если один арабский сектор
переведён двумя русскими, русские получают суффикс:
```
ar:  <!-- s050 -->            ru:  <!-- s050a -->
                                   <!-- s050b -->
```
Приложение группирует `s050a`, `s050b` под базовым id `s050` и показывает их как
**одну пару** (арабский сектор напротив склейки русских). Базовый id = id без хвостовой
буквы. Симметрично возможен обратный случай (`s050a/b` в `ar`, один `s050` в `ru`).

### 3.3 Сноска
- Текст сносок — **блоком в конце файла главы**.
- Якорь сноски: `<!-- fn073 -->` на отдельной строке перед текстом сноски.
- Ссылка на сноску внутри сектора — маркер вида `[^73]` (как в Markdown/Obsidian).
- Сноски **пер-язычные**: нумерация и текст у каждого языка свои, между языками НЕ
  спариваются. Авторские сноски-цитаты (в `ar`) и пояснения переводчика (только в `ru`)
  — разной природы и числа. Ссылка `[^N]` ведёт к сноске `fnN` **того же языка**; в
  показе одного языка сноски другого скрыты целиком. (Если у книги сноски всё же
  переводы друг друга — они просто покажутся двумя отдельными записями.)
- Многоабзацные сноски: абзацы внутри сноски разделяются пустой строкой; сноска
  заканчивается на следующем якоре `<!-- fnNNN -->` или конце файла.

### 3.4 Страница (для навигации и будущих сканов)
- Маркер: `<!-- p152 -->` на отдельной строке перед сектором.
- Ставится **ТОЛЬКО в `ar/`**. В `ru/` маркеров страниц НЕТ.
- Относится ко всем последующим секторам **до следующего** `<!-- pNNN -->`.
- Нумерация **сквозная по всему тому** (p1…p600). Значит `pNNN` глобально уникально.
- Парсер строит карту `sectorId → page` из `ar/`, затем **протягивает** page на русские
  сектора по совпадению id. Русский сектор без арабской пары останется без page —
  это **сигнал ошибки выравнивания** (см. 6, валидатор).

### 3.4a Иллюстрация в тексте (график, схема, пояснение)
- Разметка: `![подпись](media/схема.png)` — **строка целиком**, внутри сектора.
  Рендерится в `<figure>` + `<figcaption>`; тап → полноэкранный просмотр (тот же, что
  у сканов, 5.8). Подпись необязательна: `![](media/x.png)` — картинка без подписи.
- **Своя на каждый язык.** Секторы пер-язычные, поэтому в `ar/` своя разметка, в `ru/`
  своя, и подпись переводится. **Один и тот же файл в обоих языках — просто одна и та
  же ссылка**; дублировать на диске не нужно (см. `books/_sample/`, сектор `s007`).
- Путь — **относительный, от папки книги** (`books/<id>/`), как `imagePattern` сканов.
  Папка — **`media/`**, НЕ `img/`: в `img/` лежат сканы целых страниц (`p1.jpg`).
- Запрещены: схема (`javascript:`, `data:`, `http:`), протокол-относительный `//`,
  абсолютный `/`, выход вверх через `..`. Такая ссылка не рендерится (остаётся текстом)
  и даёт ошибку валидатора.
- **Инлайн внутри абзаца не поддержан** намеренно — для схем это блок. `![…](…)`
  посреди строки даст предупреждение валидатора, а не молча-голый markdown.
- **Картинка не обязана быть в обоих языках.** Только в `ru` — законно, сектор станет
  `.solo` (во всю ширину). Но в мастере Вычитки это влияет на **посекторный паритет**:
  - картинка **отдельным абзацем** (пустая строка вокруг) = **лишний сектор** → в
    строгопаритетной книге (Тауфик) счёт ar↔ru разойдётся и оригинал уедет в заглушку;
  - картинка **прицеплена** к абзацу (без пустой строки перед ней) живёт внутри
    существующего сектора и паритет **не трогает** — так и надо ставить картинку
    только в перевод;
  - в **гибридных** книгах (на якорях `<!-- sNNN -->`) паритет не нужен вовсе —
    картинка отдельным сектором только в одном языке совершенно законна.
  Конвертер, разойдясь в счёте, сам подскажет, если виноваты картинки (`parityHint`).
- Валидатор проверяет **существование файла**: битая ссылка = ошибка Контракта, а
  значит блокирует деплой в CI.

### 3.4d Листалка — объяснение в кадрах (18.10.2026)
Несколько картинок-кадров в одном месте книги, которые листаются, как альбом в Telegram
или визуальный тафсир в «Библиотеке тафсиров».
```
> [!slides] Кто как исполняет Фатиху
> ![Имам читает вслух — за всех.](media/fatiha-1.png)
> ![Стоящий за ним слушает.](media/fatiha-2.png)
> ![И отвечает «амин».](media/fatiha-3.png)
```
- Callout типа `slides`, внутри — строки-картинки по правилам 3.4a (путь `media/…`,
  подпись в `[…]` — подпись кадра). Заголовок после `[!slides]` необязателен. Строки,
  которые не картинки, идут обычным текстом под листалкой. Пустых строк внутри нет —
  листалка живёт в одном секторе.
- Вид: кадр почти во всю ширину колонки (88 %), край следующего выглядывает справа;
  в углу счётчик «1 / N», по бокам стрелки, под кадром точки — сразу видно, что это не
  одна картинка. Свайп, стрелки, точки, ←/→ с клавиатуры (когда листалка в фокусе).
  Свайп по листалке главу не перелистывает. Высота подстраивается под текущий кадр.
- Тап по кадру или «⤢» — во весь экран на тёмном фоне, листается так же; «✕» или Esc —
  обратно, на том же кадре.
- **Кадры лучше делать одной пропорции.** Для телефона — вертикальные (4:5 или 3:4):
  такой кадр занимает почти весь экран. Альбомный 16:9 на телефоне мелок — его
  разворачивают тапом во весь экран.
- Вне читалки (Obsidian, сайт) это обычный callout с картинками столбиком — разметка не
  ломается. Валидатор проверяет файлы кадров, как у 3.4a.

### 3.4e Режим «комикс» — книга кадр за кадром (18.10.2026)
- `book.json`: `"view": "comic"` — книга открывается сразу листанием во весь экран (тёмный
  фон, кадр по центру, подпись под ним, полоса прогресса, выбор главы, ✕ — к тексту).
  У обычной книги, где есть листалки или иллюстрации, внизу справа кнопка «▶ Листать».
- Отдельного формата нет — кадры собираются из главы: кадр листалки (3.4d) и иллюстрация
  (3.4a) — кадр-картинка с подписью; текст между ними — карточка (короткие абзацы
  сливаются, сноски не идут); начало главы — титул (если глав больше одной). Заголовок
  листалки, совпадающий с названием главы, не повторяется.
- Главы стыкуются: за последним кадром главы — первый следующей. Место — `{chapter, frame}`.
- Внизу — **ползунок по всей книге** (счёт «кадр N из всех»): быстро перейти к любому кадру.
- Широкий кадр на вертикальном экране — подсказка «↻ Поверните телефон — кадр станет крупнее»:
  раз за открытие комикса, первые три открытия (`settings.rotateHints`), гаснет через 3 с
  или сразу после поворота.
- В книге-комиксе у листалки нет своего полноэкранного показа: ⤢ и тап по кадру открывают
  сам комикс с этого кадра (иначе из листалки нельзя перейти к следующей главе-уроку).
- Листание: свайп, тап (левая треть — назад, остальное — вперёд; по карточке текста тап не
  листает), ←/→, PageUp/PageDown, пробел; Esc и системное «назад» закрывают комикс.
- Источники книг-комиксов: `apps/slaidy-arab/сборка/в-читалку.py` (уроки курса из PDF),
  `texts/tafsir-na-palcah/слои/визуальный/в-читалку.py` (визуальный тафсир).

### 3.4h «Ясный разбор» — статья по шагам (22.11.2026)

> **Статус.** Режим сделан 22.11.2026 (оболочка `chitalka-v88`): кнопка в шапке статьи,
> значок в ленте, показ во весь экран, адрес кадра, проверка валидатором, сведения в реестре.
> Первый разбор — `books/fatiha/razbor.json` (перенос пробы
> `~/projects/texts/obyasnyatory/roliki/fatiha-proba/`). Код — блок «ЯСНЫЙ РАЗБОР» в `app.js`,
> общее с инструментами (`razborFile`, `razborCounts`, `razborCheck`) — в `parser.js`.
> С 22.11.2026 разбор **делается сам при выкладке статьи**: конвертер `в-читалку.py` зовёт
> `tools/razbor-sdelat.js` (кадры пишет модель, арабский вырезается из статьи по номеру места,
> проверка — `razborCheck`). Порядок — CLAUDE.md, раздел «Ясный разбор».

**Что это.** Та же статья, поданная по шагам: вопрос → позиция → доводы → возражения →
итог → оговорка → проверка себя. Один кадр — одна мысль. Это **третий способ прочитать
статью**, по глубине между двумя имеющимися:

| | «Кратко» | «Ясный разбор» | «Полностью» |
|---|---|---|---|
| Что | ответ в одно-два предложения | 6–10 кадров (не считая «дальше»), пара минут | вся статья со сносками |
| Где сейчас | министатья (3.6, «Краткий ответ»); со статьёй её связывает поле `brief` | этот раздел | статья (3.6) |

- **Не отдельный сайт и не отдельная запись.** Разбор живёт при статье: тот же `id`, тот же
  адрес (`?book=<id>`), та же строка в реестре, тот же поиск (ищется статья; тексты разбора
  в `search.json` не идут — это выжимка той же статьи, выдача удвоилась бы).
- **Движок один, разборы — данные.** Вёрстку кадров рисует читалка; при статье лежит только
  файл с кадрами. Новый разбор — новый файл, а не новая страница.
- Название — «Ясный разбор» (в одном ряду с «Ясным шархом» и ясными тафсирами).

**Где живёт разбор — один на тему** (решение хозяина 22.11.2026):

| Что есть по теме | Где разбор | Что в шапке |
|---|---|---|
| только полная статья | у статьи, 6–10 кадров | кнопка «Ясный разбор · N мин» |
| только министатья | у министатьи, 4–5 кадров | кнопка «Ясный разбор · N мин» |
| и статья, и министатья (`brief`) | у полной статьи | в обеих переключатель «Кратко / Ясный разбор / Полностью»; из министатьи «Ясный разбор» открывает разбор полной (`?book=<статья>&razbor`, «назад» — в статью) |

Появилась полная статья к министатье, у которой был свой разбор, — разбор переделать под
полную (у неё больше доводов и оговорок), а у министатьи убрать. Два разбора на тему
`tools/doctor.js` отмечает: разбор министатьи при полной читатель не увидит.

**Показ** — на весь экран, как «комикс» (3.4e), и на его основе:
- свайп; тап по третям, как в комиксе (левая треть — назад, остальное — вперёд); ←/→, PageUp/PageDown, пробел — вперёд; Esc и системное «назад» закрывают
  разбор и возвращают к статье на то же место. По кадру с кнопками (проверка, ссылки) тап
  не листает — как по карточке текста в комиксе.
- сверху — **полоса хода**: по отрезку на кадр (как в пробе и в историях Telegram);
- арабский — справа налево, шрифтом и размером арабского из настроек; у Корана движок сам
  ставит ﴿…﴾ (в данных скобок нет).
- у кадра со `src` внизу — «Подробнее в статье →»: разбор закрывается, статья встаёт на
  этот раздел или абзац (абзац мигает подсветкой);
- последний кадр всегда даёт две кнопки: «Читать полностью» (статья с начала) и «Ещё раз».
- место в разборе помнится отдельно от места в статье. ⚠️ Пройденный разбор статью
  «прочитанной» не делает: состояние чтения (`readState`) — про текст статьи.
- Оформление — всегда тёмная сцена с золотом, как у комикса, при любой теме читалки
  (решение автора 22.11.2026: так дороже). Кадр при этом не картинка, а вёрстка: текст
  читается и копируется.

**Где кнопка.**
- В шапке статьи (`articleHead`) рядом с «Содержанием» — «Ясный разбор · N мин»; у статьи
  с кратким ответом (поле `brief`, 3.6) — в переключателе «Кратко / Ясный разбор / Полностью».
- На карточке ленты — небольшой значок (SVG из спрайта, не эмодзи) с подписью «разбор»;
  в подписи типа там, где записи вперемешку (поиск, «Продолжить»), — не нужен.
- В министатье, если у неё есть разбор, — так же в шапке.
- `N мин` — `readTime` от слов разбора (тот же счёт, что у статьи, 200 слов в минуту,
  не меньше 1 мин). Слова считаются по показанным полям, `say` не в счёт.

**Адрес.** `?book=<id>&razbor=<кадр>` — кадр с единицы; `?book=<id>&razbor` или `razbor=1`
— с начала; номер больше числа кадров — первый кадр. Открыть разбор — новый шаг истории
(`navPush`): «назад» возвращает в статью. Смена кадра адрес правит на месте
(`replaceState`), шагов в историю не добавляет. Это параметр записи, как `c` и `s`, а не
полки (5.9); вне чтения он не пишется. Ссылка на кадр сдвинется, если в разбор вставят
кадр раньше, — цена простого номера; разбор короткий, ссылки на кадры редки.

**Данные.** Файл `razbor.json` в папке записи (`books/<id>/razbor.json`) и поле в `book.json`:

```json
{ "razbor": "razbor.json" }
```

Так же подключён глоссарий (3.4f). Поле есть — кнопка есть; нет — разбора нет. Для статьи
на другом языке позже — объект по языкам: `"razbor": { "ru": "razbor.json", "en": "razbor.en.json" }`
(показывается разбор языка чтения). Чтобы карточка ленты знала о разборе без загрузки
манифеста, `tools/gen-meta.js` пишет в запись реестра `"razbor": { "frames": 11, "words": 325 }`
— производное, руками не пишется (как `counts` и `description`, 3.6); устарело — скажет
`tools/doctor.js`. Отдельным полем, а не внутри `counts`: `counts` считает и Вычитка, а
разборов она не знает.

```json
{ "v": 1, "lang": "ru", "title": "Фатиха за имамом", "sub": "Разбор за пару минут",
  "frames": [
    { "type": "question", "title": "Читать ли Фатиху за имамом?",
      "text": "Три текста — и один вывод", "say": "…" },
    { "type": "proof", "n": "1", "title": "Фатиха обязательна",
      "ar": "لَا صَلَاةَ لِمَنْ لَمْ يَقْرَأْ بِفَاتِحَةِ الْكِتَابِ",
      "tr": "«Нет молитвы у того, кто не прочёл Открывающую Книгу»",
      "ref": "аль-Бухари № 756 · Муслим № 394", "src": { "c": 2, "s": "s004" } }
  ] }
```

Общие поля кадра — `type` (вид, ниже) и необязательные:
- `title` — заголовок кадра;
- `src` — откуда кадр взят в статье: `{ "c": <глава с единицы>, "s": "<сектор>" }`. Нужен
  для сверки (кадр ↔ место статьи) и для перехода «подробнее»; у довода, позиции,
  возражения, оговорки ставится всегда. Глава + сектор, а не один сектор: `s003` есть в
  каждой главе (3.6, «Ссылка на абзац»);
- `say` — текст для будущей озвучки и ролика (ударение — `+` перед гласной, как в пробе).
  На экран не выводится. Кадр без `say` в ролик не идёт (так в пробе устроена проверка);
- `img` — картинка кадра по правилам 3.4a (`media/…`), если кадру нужна наглядность.

В текстовых полях — инлайн-разметка Контракта (`**жирный**`, `*курсив*`, `<u>…</u>`);
сносок `[^N]` нет: адрес довода — в `ref`, подробности — в статье.

**Виды кадров** (`type`):

| `type` | Вид | Поля | Что в нём |
|---|---|---|---|
| `question` | вопрос | `title`, `text` | вопрос, как его спросил бы человек; подзаголовок — что будет |
| `position` | позиция | `text`, `src` | ответ автора **его словами** из статьи |
| `proof` | довод | `n`, `title`, `ar`, `quran`, `tr`, `ref`, `note`, `src` | арабский текст, перевод, адрес, пояснение в одну строку; `quran: true` — это аят (скобки ﴿﴾, оформление Корана) |
| `objection` | возражение | `title`, `claim` (их довод: `text`, опц. `ar`, `quran`, `tr`, `ref`), `answer` (`text`, опц. `ar`, `quran`, `tr`, `ref`), `src` | довод другой стороны — и ответ на него, двумя частями одного кадра |
| `scheme` | схема | `title`, `rows` или `img` | простая наглядность: `rows` — 2–4 плашки со стрелкой между ними (`[{ "label": "Слышишь", "text": "слушай и говори «амин»" }]`), либо картинка |
| `summary` | итог | `title`, `fork`, `quote` | развилка «если → то» (`[{ "if": "…", "then": "…" }]`) и цитата автора, которой он сам подводит итог |
| `caveat` | оговорка | `kind`, `title`, `text`, `src` | `kind`: `ijtihad` (это иджтихад автора), `khilaf` (признанное разногласие), `limits` (где вывод не работает) |
| `check` | проверка | `q`, `options` (`[{ "text": "…", "ok": true, "why": "…" }]`) | вопрос-случай, 2–4 варианта; после выбора — «верно / неверно» и разбор |
| `next` | дальше | `text`, `links` (`[{ "label": "…", "c": 3, "s": "s010" }]`) | куда читать в полной статье: ссылка открывает статью на этом разделе или абзаце (`pairAt(глава, сектор)`); без `label` подписью встаёт название главы |

Порядок кадров задаёт автор. Обычный ход: `question` → `position` → `proof`… →
`objection`… → `summary` → `caveat` → `check` → `next`. Схема — где помогает глазу.

**Правила содержания** (их проверяет готовящий разбор, а потом — валидатор):
- **Арабский — только дословно из вырезок статьи.** Каждое поле `ar` (в доводе, возражении,
  ответе) — точная подстрока текста статьи после NFC: огласовки, порядок знаков, слова.
  Проверка скриптом обязательна (как `proverit-arabskiy.py` в пробе); в читалке её будет
  делать `tools/validate.js`, и расхождение станет ошибкой Контракта — деплой не пройдёт.
- **Позиция и оговорки — словами автора.** `position`, `caveat` и `quote` в `summary` берутся
  из статьи (можно сократить, нельзя пересказать своими словами и нельзя усилить вывод).
  Пересказ допустим только в связках: заголовки, вопрос, пояснение в одну строку.
- **Кадр-оговорка обязателен**, где статья помечает вывод как иджтихад, говорит о признанном
  разногласии или ставит границы вывода. Разбор без него читается как «так говорит шариат»,
  а не «так предпочёл автор».
- Довод другой стороны, который статья разбирает, в разборе не выкидывается — `objection`.
- **Объём:** разбор статьи — 6–10 кадров, министатьи — 4–5; кадры `question` и `next` не в счёт. Больше — значит в кадрах уже
  пересказ статьи, а не её ход.
- Ничего, чего нет в статье: ни нового довода, ни нового адреса. Разбор — подача той же
  статьи, не новое исследование.

**Валидатор** (`tools/validate.js`, ошибка = деплой не пройдёт). `razbor.json` разбирается; `type` известен; у каждого вида
есть обязательные поля; `src` и ссылки `next` указывают на существующие главу и сектор;
файлы `img` есть (3.4a); каждое `ar` найдено в тексте статьи; у `check` хотя бы один
вариант с `ok: true`. Нет поля `razbor` в `book.json` — проверять нечего.

**Перенос пробы в формат** (так сделан `books/fatiha/razbor.json`). Кадры пробы (`stsenariy.js`, ключи по-русски) ложатся так:
`титул` → `question`, `довод` → `proof` (`номер` → `n`, `арабский` → `ar`, `коран` → `quran`,
`перевод` → `tr`, `адрес` → `ref`, `пояснение` → `note`), `итог` → `summary` (`развилка` →
`fork`: `если`/`то` → `if`/`then`; `цитата` → `quote`), `конец` → `caveat` с `kind:
"khilaf"` + `next`, `проверка` → `check` (`вопрос` → `q`, `варианты` → `options`: `верно`
→ `ok`, `разбор` → `why`), `скажи` → `say`. В пробе нет `position`, `objection` и `src` —
при переносе их добавить: у статьи «Фатиха за имамом» разобраны доводы другой стороны.

### 3.4b Таблица и блок формул (справочники)

Добавлены 2026-07-25 под справочные книги: словари терминов, таблицы соответствий,
парадигмы, формальная запись. До этого такой материал в Контракт не укладывался.

**Таблица** — разметка GFM, внутри сектора:

```
| Латынь | Арабский | Смысл |
|---|:--:|--:|
| **genus** | джинс (`jins`) | род |
```

- Шапка + **строка-разделитель** из дефисов; без разделителя это обычный абзац.
- Двоеточия в разделителе задают выравнивание колонки: `:--` слева, `--:` справа,
  `:-:` по центру. Приходит инлайн-стилем и побеждает стили таблицы.
- Внутри ячейки работает инлайн-разметка (`**жирный**`, `` `код` ``, `[^N]`).
  Символ `|` внутри ячейки экранируется: `\|`.
- Рендерится в `<table>` внутри `.table-wrap` — **обёртка со своей горизонтальной
  прокруткой**: широкая таблица прокручивается внутри себя и не разъезжает страницу
  вбок на телефоне. Шапка липкая при прокрутке.
- **Картинкой таблицы не верстать.** Изображение не находится поиском, из него не
  скопировать термин, оно не переносится по ширине, не слушается размера шрифта и
  остаётся светлым в тёмной теме. Для справочника это худший вариант.

**Блок формул и ASCII-схем** — тройная ограда:

```
        A ──── contrariae ──── E
        I ── subcontrariae ── O
```

- Моноширинно, разметка внутри не разбирается, **отступы сохраняются** (в обычных
  строках пробелы в начале срезаются — внутри ограды нет).
- Своя горизонтальная прокрутка; всегда `direction: ltr` — формулы читаются слева
  направо даже в RTL-книге.
- **Пустая строка внутри ограды разрешена** и сектор не завершает — это исключение
  из правила 3.2. Незакрытая ограда портит только свой сектор: следующий якорь
  `<!-- sNNN -->` сбрасывает её.
- То же понимает `contract.js` при публикации из Вычитки: внутри ограды `---` и
  `## …` не считаются разделителем блока и заголовком.

**Инлайн-код** — `` `mantiq` `` в обратных кавычках, в любом абзаце, ячейке и списке.
Разбирается **первым**, поэтому звёздочки и подчёркивания внутри термина остаются
символами, а не курсивом.

### 3.4f Глоссарий книги — статья по нажатию на термин (18.10.2026)
- Разметка в тексте — та же, что в мастере Obsidian: `` [`термин`](glossary.md#якорь) `` или
  `[слово](glossary.md#якорь)`; путь к файлу любой (`glossary.md`, `../glossary.md`,
  `1/glossary.md`). Якорь сравнивается без регистра, пробел = дефис, `%`-коды
  раскодируются. Рисуется кнопкой `.gterm` (слово с пунктиром), подпись — без обратных кавычек.
- Словарь — `book.json` → `"glossary": "glossary.json"`, файл
  `{ "entries": { "якорь": { "term": "‘амм", "md": "…markdown статьи…" } } }`. Статья —
  абзацы через пустую строку, внутри тот же markdown, что в секторе; ссылки на другие
  термины работают внутри плашки (с «← назад»). Собирает его `tools/import-glossary.js`
  из мастера `## якорь` (вики-ссылки → подпись).
- Нет словаря у книги — термин остаётся обычным словом. Валидатор: якорь без статьи = ошибка.

### 3.4g Шарх у абзаца — значок 💡 и статья в панели (18.10.2026)
- Ссылка на статью шарха — callout в **скрытой заметке сразу после абзаца**:
  ```
  <!-- note -->
  > [!caution] Шарх: [[392-Амм по лицам…|‘Амм по лицам, мутляк по состояниям]]
  <!-- /note -->
  ```
  Тип callout любой, важно слово «Шарх:» в заголовке. Заметка при чтении скрыта, как и
  прежде; ссылка привязывается к последнему абзацу с текстом перед ней (пустые якоря,
  которые конвертер ставит внутри заметки, пропускаются). Несколько заметок — вкладки.
- Книга шарха — одноязычная книга (`languages: ["ru"]`, `"type": "sharh"`), глава = статья;
  у главы `title` и опц. `key` (имя файла мастера). `book.json` текста: `"sharh": "<id>"`.
  Статья ищется по подписи ссылки: совпасть должен `title` или `key` без номера страницы в
  начале, регистра и знаков (`sharhKey`). Книга шарха может не стоять на полке — тогда
  берётся `books/<id>/`. Собирает её `tools/import-sharh.js` из папки статей Obsidian.
- Читалка: у абзаца 💡 → панель (справа на широком экране, снизу на телефоне) со статьёй,
  её сносками и терминами; «Открыть в книге шарха» ведёт туда целиком, «назад» — к тому
  же абзацу. Валидатор: нет книги шарха или статьи с таким названием = ошибка.

### 3.5 Манифест `book.json`
```json
{
  "bookId": "tawfiq-al-mannan-v2",
  "title": { "ar": "...", "ru": "Тауфик аль-маннан, т.2" },
  "languages": ["ar", "ru"],
  "rtl": ["ar"],
  "chapters": [
    { "file": "01.md", "title": { "ar": "...", "ru": "Вступление" } },
    { "file": "07.md", "title": { "ar": "...", "ru": "Защита Ибн Таймийи (2/3)" } }
  ],
  "hasImages": true,
  "imagePattern": "img/p{page}.jpg"
}
```
- `rtl` — список языков, рендерящихся справа-налево. Направление берётся **из языка
  контента**, не из позиции окна.
- `chapters` задаёт порядок и оглавление.

### 3.6 Тип записи: книга или статья (14.11.2026)

Запись библиотеки бывает **книгой** или **статьёй**. Формат текста один — Контракт
(разделы 3.1–3.5), движок один; различаются тип записи в реестре и подача.

**Критерий.** Статья отвечает на один вопрос и читается за один присест. Книга — много
тем и главы, которые читают по отдельности. Число слов — подсказка, а не правило:
статьи-разборы сейчас занимают 2–12 тыс. слов, книги — от 19 тыс.

**В реестре** (`books/index.json`, запись книги):

```json
{ "id": "posuda", "base": "books/posuda/", "title": { "ru": "Накрывайте посуду" },
  "kind": "article", "date": "2026-11-13",
  "counts": { "chapters": 8, "words": 2325 },
  "description": "Насколько строг приказ накрывать на ночь посуду…" }
```

- `kind` — `"article"` или `"book"`; нет поля — книга. Другое значение — ошибка
  (`tools/doctor.js`). **`id` и адреса от типа не зависят**: `?book=<id>` открывает и
  книгу, и статью, смена типа ссылок не ломает.
- `date` — день публикации статьи, `ГГГГ-ММ-ДД`. По ней лента стоит «сначала новые»;
  видна в карточке («нояб. 2026») и в шапке статьи («13 нояб. 2026»).
- `counts.chapters`, `counts.words` — число глав с текстом и слов основного текста (без
  сносок) на языке чтения. `description` — копия аннотации из `book.json`, только у
  статей. Оба поля **производные**, руками их не правят (кто пишет — ниже).
- Непубличные книги: реестр выводится из манифестов (`tools/private-index.js`), поэтому
  у них `kind` и `date` стоят в `book.json`.

**Кто ставит тип и считает сведения** (с 15.11.2026). Издателей три, счёт один:

| Откуда запись | Тип и дата | `counts`, `description` |
|---|---|---|
| конвертер статей `~/projects/tools/statya/в-читалку.py` | сам: `article`, день запуска | зовёт `tools/gen-meta.js` |
| Вычитка, «Опубликовать в библиотеку» | автор выбирает в форме «Книга / Статья»; дата — сегодня, правится | считает сама тем же кодом, по записанным файлам |
| руками, импортёры `tools/import-*.js` | руками в реестре | `node tools/gen-meta.js` |

- **Счёт — в `contract.js`** (`shelfCounts`, `shelfMeta`), а не в `gen-meta.js`: это
  единственный файл, общий у читалки (Node) и Вычитки (браузер). `gen-meta.js` только
  читает папку книги с диска и отдаёт тексты ядру. Второго счётчика не заводить: разойдись
  он хоть на слово, `tools/doctor.js` объявит запись, опубликованную из Вычитки, устаревшей.
- **Считается текст Контракта, а не отрисованная страница.** Слово — цепочка букв и цифр
  (дефис и апостроф внутри его не рвут), только в текст-секторах на языке чтения (русский,
  иначе последний язык книги). Не слова: сноски, личные заметки `<!-- note -->`, номер
  сноски `[^N]` и пункта списка, адрес картинки и ссылки, тип врезки `[!note]`. Подпись
  картинки и текст ссылки — слова. Счёт по отрисованному html (так было один день, 14.11)
  прибавлял то, чего автор не писал: подпись «Примечание» у врезки без заголовка, счётчик
  кадров листалки, — и менялся бы от любой правки отрисовки.
- **Догадка о типе для новой записи** (`guessKind`): статья, если в оглавлении нет
  записей-групп (частей) и слов не больше 15 000 (около 75 минут чтения). Это только
  значение по умолчанию в форме Вычитки. Выбор автора важнее; у записи, которая уже есть в
  реестре, форма показывает её тип, а смену типа называет прямо («тип поменяется»).

**Подача.**

| | Книга | Статья |
|---|---|---|
| На полке | вкладка «Книги»: обложка на деревянной полке (или корешки, список) | вкладка «Статьи»: лента карточек — небольшая плоская обложка слева, справа заголовок, две строки аннотации, раздел, время чтения, дата |
| Открытие | карточка книги → «Читать» | сразу текст; то, что показала бы карточка, стоит в шапке статьи |
| Чтение | по главам, «Следующая глава →» | одной страницей: главы идут подряд как разделы с заголовками |
| Сноски | свои у каждой главы | концевые, одним списком; номера сквозные по всей статье |
| Оглавление | «Главы» — открывает главу | «Разделы» — прокручивает к разделу |
| Прогресс | глава + доля главы | доля прокрутки до конца текста (сноски не в счёт) |
| Подпись типа | «Книга · 37 глав» | «Статья · 14 мин» |

- Время чтения — `counts.words / 200`, округлённо до минуты; от часа — «1 ч 5 мин».
- Обложка у статьи необязательна: нет картинки — в ленте рисованная заглушка (как у
  книги без обложки), в шапке статьи обложки просто нет.
- Подпись типа стоит там, где книги и статьи вперемешку: поиск по всей библиотеке,
  строка «Продолжить», вырезки.
- Рубрикатор, теги, фасеты, поиск, сноски, закладки и пометки — общие. Дерево разделов
  считает записи открытой вкладки; запрос, нашедшийся только в соседней вкладке,
  показывается строкой «Во вкладке … по этому запросу — N».
- `"view": "comic"` в `book.json` сильнее типа: такая запись листается кадрами по главам.

**Сноски статьи.** В файлах счёт сносок у каждой главы свой, с единицы (3.3) — это не
меняется. Одной страницей «¹» в двух разделах подряд читались бы как одна сноска,
поэтому **показывается** сквозной номер по порядку во всей статье; в данных и в
`data-fn` остаётся номер из файла, по нему (вместе с главой) сноска и находится.

**Ссылка на абзац.** `?book=<id>&c=<глава>&s=<сектор>`, глава — с единицы. Сектор `s004`
есть в каждой главе, поэтому без главы ссылка неоднозначна; старые ссылки без `c`
открывают первую главу, где сектор нашёлся (как раньше).

#### Краткий ответ (16.11.2026)

Статья с `"genre": ["Краткий ответ"]` — министатья: готовый ответ автора на один вопрос, 1–3
экрана, из его базы знаний. Тип записи тот же (`article`); жанр даёт метку «Краткий ответ» в
ленте и в шапке, подпись «Краткий ответ · N мин» вместо «Статья · N мин» и чипы «Краткие
ответы» / «Исследования» на вкладке «Статьи» (адрес полки — `form=brief|full`). Выкладывает
конвертер статей по шапке министатьи (`вид: министатья`), формат министатьи —
`~/.claude/skills/otvety/министатья.md`.

**Связь статьи с её кратким ответом** (решение хозяина 22.11.2026, сделано тогда же).
Поле `"brief": "<id министатьи>"` в записи **статьи** в `books/index.json`:

```json
{ "id": "fatiha", "kind": "article", "brief": "fatiha-kratko", "…": "…" }
```

- Ставится руками в реестре или в `РЕЕСТР` реквизитов конвертера статей. Обратной ссылки
  у министатьи не пишут: читалка находит статью сама — запись, у которой `brief` равен id
  министатьи.
- В шапке статьи — переключатель трёх способов чтения: «Кратко» (переход к министатье,
  `?book=<brief>`), «Ясный разбор» (если есть, 3.4h), «Полностью» (сама статья, отмечен).
  В шапке министатьи тот же переключатель: «Полностью» ведёт в статью. Нет `brief` — нет
  и «Кратко»; кнопка «Ясный разбор» тогда стоит одна, как в 3.4h.
- `tools/doctor.js` проверяет: `brief` указывает на существующую запись с жанром
  «Краткий ответ»; одна министатья — краткий ответ не больше чем одной статьи.
- Министатья и статья остаются двумя записями: своя дата, своя строка в ленте, свой
  поиск. `brief` их только связывает.

#### Поля полки: закреплённое и серии (15.11.2026)

Необязательные поля записи в `books/index.json`; ставит автор, руками:

- `"pinned": N` — запись стоит в блоке «Начните отсюда» над списком своей вкладки; `N` —
  порядок в блоке (положительное число, меньшее — выше). Блок виден только над полным
  списком: под поиском, чипами и фильтрами его нет.
- `"series": "Название"` и `"part": N` — запись входит в серию; в ленте, в «Начните отсюда»
  и в «Что читать дальше» подписывается «часть N из M». `M` читалка считает сама: старший
  номер части среди записей с тем же `series` (черновики считаются — часть уже объявлена),
  но не меньше числа таких записей. Серия из одной записи не подписывается. Одна часть —
  одна запись; номера с единицы.

Проверяет `tools/doctor.js`: тип полей, `part` без `series`, занятый номер части.

#### Соседние разборы «По этому вопросу» (решение хозяина 23.11.2026)

Под «Концом статьи» стоит блок «Что читать дальше». Раньше он брал только следующую часть
серии, свежее непрочитанное из того же раздела и просто свежее непрочитанное. Тему такой
подбор не ловит: под «Фатихой за имамом» вставало «Мясо суфия-мушрика», а общий у них только
раздел «Ибадат». Поэтому автор подбирает соседей сам:

```json
{ "id": "muha", "related": [
  { "id": "tavil", "why": "Тот же тавиль — в толковании текстов о качествах: когда он становится куфром" },
  { "id": "otvet-myaso", "why": "Соседний случай: режет мушрик, но не ради идола" } ] }
```

- Соседи стоят в блоке первыми, сразу после следующей части серии, под подзаголовком «По
  этому вопросу». Над каждым его причина (`why`) на месте серой подписи. Автоматические
  карточки идут ниже, под подзаголовком «Ещё». Если у записи нет `related`, блок выглядит
  как раньше, без подзаголовков.
- Соседей показывают, даже если читатель их уже прочёл: их выбрал автор, а счёт
  непрочитанного здесь ни при чём. У прочитанного в строке времени стоит «прочитано», у
  министатьи — «Краткий ответ».
- Соседом бывает только одно из четырёх: основа вывода; то же понятие в другом смысле или
  на другом материале; соседний случай, который статья оставила за рамкой; возражение или
  следующий вопрос, разобранные отдельно. Тот же раздел или свежесть поводом не считаются.
  Статью и её краткий ответ связывает `brief`, а не `related`. Правило подбора — скилл
  `statya`, §7.3.
- **Связь пишется в обе стороны, у каждой стороны своя причина.** Обратную связь читалка
  не достраивает: причина, написанная с одной стороны, с другой звучит неверно.
- Поле стоит руками в `books/index.json`. Конвертер статей не трогает запись, которая уже
  есть в реестре, поэтому поле переживает перевыкладку.
- `tools/doctor.js` проверяет: запись-сосед есть в реестре, у соседа есть причина длиной
  до 80 знаков, соседей не больше трёх, нет ссылки на себя и на свой краткий ответ,
  у соседа есть обратная ссылка.

### 3.7 Поисковый файл `search.json` (15.11.2026)

Производный файл: весь текст записи, уже разобранный на секторы. Нужен поиску по
библиотеке, чтобы брать книгу одним запросом, а не всеми главами. Руками не правится —
собирается `tools/gen-search.js` (его зовёт `tools/gen-meta.js`) из тех же файлов Контракта.

```json
{ "v": 1, "langs": ["ar", "ru"], "rtl": ["ar"], "c": { "chapters": 37, "words": 58700 },
  "ch": [ { "i": 0, "t": "Вступление",
            "p": [ ["s001", "текст на ar", "текст на ru"], ["fn3", null, "текст сноски"] ] } ] }
```

- `i` — номер главы в `book.json.chapters`; `t` — её название для выдачи (русское, если есть);
- `p` — строки: id сектора и текст на каждом языке из `langs` по порядку; нет текста — `null`.
  Сноски идут своими строками: они пер-язычные (3.3), текст стоит только у своего языка.
- Текст — то, что видит читатель: без разметки, сущности развёрнуты (`parser.js`, `htmlPlain`).
  По смещениям в этой строке поиск красит найденное в отрисованной главе, поэтому файл и
  читалка собирают её одним кодом (`searchIndex`).
- `c` — число глав и слов, тем же счётом, что `counts` в реестре (`contract.js`). По нему
  читалка узнаёт файл, отставший от текста: числа в реестре и в файле не сошлись — файл не
  берём.
- Файла нет или он отстал — читалка собирает то же самое из глав на месте (медленно).
  За свежестью следит и `tools/doctor.js`.

## 4. МОДЕЛЬ ДАННЫХ (ядро)

Парсер на входе берёт `ar/NN.md` + `ru/NN.md`, на выходе даёт **массив пар**:

```js
// одна глава →
[
  {
    id: "s007",          // базовый id
    page: 152,           // из ar, протянуто; null если неизвестно
    type: "text",        // "text" | "footnote"
    ar: "…html сектора…", // inline-markdown → html; null если нет
    ru: "…html…",        // null если нет
    refs: ["73","74"]     // id сносок, на которые ссылается этот сектор (из [^N])
  },
  …
]
```

- **Всё остальное в приложении — функции отрисовки над этим массивом.** Раскладки,
  видимость языков, сноски — это представление одной модели. Нельзя дублировать данные
  под разные режимы.
- Сноски — те же элементы массива с `type:"footnote"`, живут логически «в конце главы».

## 5. РЕЖИМЫ ОТОБРАЖЕНИЯ (состояние поверх ядра — НЕ отдельные архитектуры)

### 5.1 Базовая раскладка — ЕДИНЫЙ ПОТОК ПАР
Поток идёт сверху вниз: для каждой пары — оба языка вместе (по умолчанию оригинал сверху,
перевод снизу). Это и «билингва для учёбы», и (через 5.2) «чтение одного языка», и (через
5.4) «две колонки». **Отдельного механизма синхронного скролла двух независимых окон НЕТ** —
пара физически слита, синхронизировать нечего.

### 5.2 Видимость языков (3 состояния, одна кнопка-переключатель)
- `both` — оба члена пары видны (дефолт);
- `ar` — виден только арабский член каждой пары → сплошное чтение арабского;
- `ru` — виден только русский → сплошное чтение перевода.
Реализация: каждый член пары — блок с переключаемой видимостью. Скрытие — `display:none`.

### 5.3 Подсветка активной пары
Тонкая полоса/заливка у пары, ближайшей к центру вьюпорта. Помогает глазу держать
соответствие. Активная пара определяется по позиции относительно центра экрана.
Видимость — настройка «Подсветка абзаца» (`settings.hlActive`): `auto` (по умолчанию —
только в книгах с переводом; в одноязычной рамка отвлекает), `always`, `never`. Сама
активная пара считается всегда: по ней ставится закладка и запоминается место.

### 5.4 Раскладка пары: вертикаль / горизонталь
- Вертикаль (телефон-портрет, дефолт): оригинал над переводом.
- Горизонталь (альбом/планшет): оригинал и перевод в две колонки (CSS `flex-direction`).
- Переключение **по ориентации экрана** автоматически + ручной тумблер в настройках.
- Это **CSS-переключение над тем же потоком**, не другая логика.

### 5.5 Направление текста
- Член пары на языке из `rtl` → `dir="rtl"`, иначе `dir="ltr"`.
- Привязано к языку контента, не к позиции. При смене языка в потоке dir пересчитывается.

### 5.6 Сноски — ДВЕ механики, переключатель в настройках
Источник один (`type:"footnote"` по id), различается только показ.
- **Инлайн-разворот (дефолт):** тап по `[^73]` → под текущим сектором раскрывается
  аккордеон с текстом сноски `fn073`; повторный тап — сворачивает. Разворачивается
  **в соответствии с текущей видимостью языков** (both → пара ar+ru).
- **Скачок-возврат:** тап по `[^73]` → `scrollIntoView` к сектору `fn073` (логически конец
  главы); запоминаем origin-id; у текста сноски — кнопка/маркер «вернуться» → скролл назад
  к origin и кратковременная подсветка маркера `[^73]`.
- Переключатель в настройках выбирает обработчик тапа.

### 5.7 Навигация
- **Оглавление** по `chapters` из манифеста. У статьи (3.6) это разделы одной страницы:
  выбор раздела прокручивает к его заголовку; стрелок глав, свайпа и перехода
  «Следующая глава» у статьи нет.
- **Переход по странице:** ввод номера → прыжок к первому сектору с `page == N`.
- Текущая страница видна в UI (из `page` активной пары).

### 5.8 Скан страницы (если `hasImages`)
- Кнопка у активной пары «показать скан» → открывает `img/p{page}.jpg` (модал/оверлей,
  с зумом). Берётся по `page` сектора, не по id — устойчиво к дроблению.

### 5.9 Адреса (15.11.2026)

Всё состояние, которым можно поделиться, лежит в параметрах адреса; сервер их не разбирает.

| Адрес | Что открывает |
|---|---|
| `?book=<id>` | запись в чтении: книга — на месте, где остановились, статья — так же |
| `?book=<id>&c=<глава>&s=<сектор>` | абзац; глава считается с единицы (см. 3.6, «Ссылка на абзац») |
| `?book=<id>&razbor=<кадр>` | «Ясный разбор» статьи на этом кадре, с единицы (3.4h, 22.11.2026); под ним в истории — сама статья |
| `?info=<id>` | карточка книги (у статьи карточки нет — такая ссылка ведёт в текст) |
| без `book` и `info` | полка |

**Параметры полки** — все необязательные:

| Параметр | Значение |
|---|---|
| `tab` | `books` или `articles` — вкладка |
| `cat` | id узла `taxonomy.json` — раздел (по id, не по названию: названия правятся) |
| `read` | `none`, `reading`, `done` — чип «Не читал / Читаю / Прочитано» |
| `len` | `short`, `long` — чип длины, только у статей |
| `form` | `brief`, `full` — чип «Краткие ответы / Исследования», только у статей (16.11.2026) |
| `review`, `progress`, `langs`, `authors`, `madhhab`, `era`, `genre`, `tags` | фильтры; несколько значений — параметр повторяется: `langs=ar&langs=ru` |
| `q` | запрос в поле поиска на полке |

Порядок и вид списка в адрес не идут: это привычка читателя, а не отбор.

Читалка пишет в адрес только то, что отличается от обычного («Книги» без отбора — чистый
адрес), и меняет его на месте, без новых шагов в истории. Читает так:

- есть хоть один параметр полки — адрес задаёт её целиком, а чего в нём нет, то обычное
  (вкладка «Книги», без раздела и отбора);
- чистый адрес при запуске — полка, какой её оставили (у установленной читалки адрес
  запуска всегда чистый);
- чистый адрес на шаге «назад» или «вперёд» — полка без отбора: адрес каждой записи
  истории читалка держит в актуальном виде.

## 6. ВАЛИДАТОР КОНТРАКТА (обязателен, дёшев, спасает книгу)

При загрузке главы приложение проверяет и **видимо сообщает** (не молча!):
- id сектора есть в `ar`, но нет пары в `ru` (или наоборот) → предупреждение со списком id;
- русский сектор без `page` (значит нет арабской пары) → тот же сигнал;
- ссылка `[^N]` в тексте без определения `fnN` в конце файла → битая сноска;
- определение `fnN` без единой ссылки `[^N]` → висячая сноша;
- открытая метка Вычитки `==?…==`, `==pro?…==`, `==pro✓…==` вне заметок → текст не готов к
  публикации (в CI это ошибка: деплой не пройдёт, пока метка жива);
- термин без статьи в глоссарии, значок шарха без статьи в книге шарха (3.4f, 3.4g).
Эти проверки — главный страхователь от тихого рассинхрона. Вывести в отладочную панель
(скрытую за настройкой «режим проверки»), чтобы при разметке тома ты ловил ошибки сразу.

### 3.4c. Подстрочник — пословные подписи

Книга может нести слой подстрочника: под каждым словом изучаемого языка — короткая
русская подпись. Объявляется в манифесте: `"gloss": ["en"]`. Файлы —
`<книга>/gloss/<язык>/<глава>.md`, имя файла совпадает с именем файла текста.

**Якорь сектора** несёт атрибуты:

    <!-- s005 h=083950351038dc ok -->
    <!-- ru: Медленный читатель с карандашом перечитает быстрого. -->

- `h=…` — хеш ПОСЛЕДОВАТЕЛЬНОСТИ СЛОВ сектора на момент генерации (`glossHash`).
  Не от html: выделили слово жирным — html другой, а номера и подписи прежние.
  По нему генератор видит, какие секторы протухли, и трогает только их.
- `ok` — сектор выверен человеком. Нет атрибута — машинная генерация.
  Перегенерация флаг снимает: проверяли не этот текст.
- `<!-- ru: … -->` — рабочий перевод модели, из которого разложены подписи.
  Читателю не показывается никогда; нужен тому, кто выверяет сектор.

**Строка слова:**

    <номер><класс> <слово> <подпись> :: <словарная форма> <уровень>

- **номер** — порядковый номер слова ВНУТРИ СЕКТОРА, с единицы, по размеченному
  тексту (`glossTokens`). Слова внутри `<code>`, `<pre>`, `<figcaption>` и кнопок
  сносок не считаются и не подписываются.
- **класс** приклеен к номеру без пробела: пусто — знаменательное слово;
  `f` — служебное (читалка по умолчанию не рисует); `n` — имя собственное
  (лицо, место, народ, название книги). Отдельной колонкой класс быть не может:
  она была бы неотличима от односимвольного слова (`a`, `I`).
- **слово** — копия слова из текста, контрольная сумма. Не совпало — подпись не
  ставится, валидатор роняет сборку.
- **подпись** — либо перевод, либо `->12`: смысл несёт слово 12, своей подписи нет.
  Отсутствие строки и намеренно пустая подпись — разные вещи, и различать их
  обязательно: первое неотличимо от потери, второе видно и глазом, и валидатору.
- **словарная форма** после ` :: ` — ключ, по которому слово из разных книг сойдётся
  в одну запись (выученные слова, уровни). Для арабского: без кратких огласовок,
  без артикля `ال`, с сохранением шадды. Огласовки снимает генератор кодом —
  просить модель писать единообразно недостаточно.
- **уровень** — цифра 1–5, насколько слово трудно (1 базовое … 5 термин).

Подписи ставятся на каждое ВХОЖДЕНИЕ слова отдельно, поэтому одно слово в разных
местах сектора законно переводится по-разному.

Подписи готовит ИИ по абзацу целиком (`tools/gloss-book.js`), руками их не пишут.
Почему не встроенный словарь лемм и почему это часть книги — `CLAUDE.md`.

## 8. ПРАВИЛА ДЛЯ КЛУДОДА (Claude Code)

1. **Сначала ядро, потом представление.** Реализуй парсер + модель пар + валидатор и
   докажи на одной главе (07), что пары и страницы собираются верно, ДО любого UI.
2. **Одна модель — много рендеров.** Не дублируй данные под режимы. Режимы — функции над
   массивом пар.
3. **Контент в рантайме.** `fetch` из `/books/<id>/…`. Никакого вшивания текста в код.
4. **Не молчать об ошибках контракта.** Рассинхрон id/страниц — видимое предупреждение,
   не тихий сдвиг.
5. **Парсер сносок/якорей — свой.** Стандартный markdown-рендерер только для inline внутри
   сектора, и то опционально.
6. **Мобайл-фёрст, без зависимостей.** Если очень нужна библиотека — сперва обосновать здесь.
7. **Тестовые данные.** Создай `/books/_sample/` с 1–2 короткими главами (ar+ru, сноски,
   страницы, группа s050a/b) для разработки без реальной книги.
8. **README** с инструкцией запуска (любой статический сервер) и описанием структуры.
