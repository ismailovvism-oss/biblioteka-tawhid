# CLAUDE.md — Параллельная читалка

Управляющий файл проекта для Claude Code. Читается автоматически. Здесь — рабочий
контекст, который иначе пришлось бы объяснять каждой новой сессии. Полная
спецификация формата — в `SPEC.md`; список идей — в `BACKLOG.md`.

> **Большая цель.** Эта читалка — слой просмотра будущей **библиотеки исламских знаний**
> (каталог, классификация, теги, полнотекстовый поиск, авторы). Целевая архитектура и
> решения (static-first с швами под бэкенд; контент отделён от приложения; сканы/PDF — в
> объектное хранилище) — в `ARCHITECTURE.md`. Развивая читалку, держи её совместимой с
> этим: стабильные id, состояние за абстракцией, формат Контракта как общий.

## Что это

Статическое веб-приложение (vanilla JS, без сборки и фреймворков) для
**параллельного чтения** книги на двух языках (оригинал + перевод), выровненных по
смысловым секторам.

> ⚠️ **Библиотека многоязычная, а не арабо-русская.** Направлений уже два (ar↔ru и
> en↔ru), дальше будут другие, **плюс планируется трёхъязычный режим** (ядро
> мультиперевода готово, см. «Состояние фич»). Отсюда правило при отборе функций:
> **не отбрасывать возможность потому, что она бесполезна для арабского** — то, что
> не работает на вязи, может быть лучшим, что есть для английского (словари с
> примерами и произношением, Bionic Reading, озвучка). Такие вещи включаются
> **по языку фрагмента**, а не глобально. Однажды по этой причине уже были
> ошибочно вычеркнуты словарные источники — см. BACKLOG, раздел про Smart Book. PWA (офлайн через `sw.js`). Запуск — любой статический сервер
(`python3 -m http.server 8000`), `file://` не годится из-за `fetch`.

Ключевые файлы:
- `index.html` / `style.css` — оболочка и стили.
- `app.js` — всё приложение (рендер, навигация, поиск, закладки, выделения, статистика, настройки).
- `parser.js` — **чистые функции Контракта без DOM**. Используется и в браузере, и в
  Node (`tools/validate.js`). НЕ добавлять сюда обращения к DOM — сломается валидатор.
- `books/` — контент. `books/index.json` — реестр; каждая книга в `books/<id>/`
  (`book.json` + папки языков). `books/_sample/` — эталонная мини-книга и тест формата.
- `gloss.js` — подстрочник: загрузка подписей главы и раскладка их по словам (браузерный,
  как `translate.js`). Нумерация и разбор файла — в `parser.js`, общие с генератором.
- `tools/gloss-book.js` — генератор подписей через ИИ (см. раздел о подстрочнике).
- `tools/validate.js` — валидатор Контракта: `node tools/validate.js books/<id>`.
- `tools/gen-meta.js` — число глав и слов (а у статьи и аннотация) → в реестр; запускать
  после добавления записи и после правки текста. `tools/gen-thumbs.js` — миниатюры обложек.
- `tools/gen-search.js` — поисковые файлы `books/<id>/search.json` (весь текст записи одним
  файлом, под поиск по библиотеке). Отдельно звать не нужно: его зовёт `gen-meta.js`.
- `tools/stend.js` — стенд для проверки кеша и скорости: статический сервер, который умеет
  «молчать» (раздел «Воркер и кеш»).
- `tools/import-tam.js` — импорт книги «Тауфик аль-Маннан» (см. ниже).

## Контракт (кратко; детали в SPEC.md)

- Сектор: `<!-- sNNN -->` перед абзацем. Текст-сектора **выровнены по id** между
  языками (`s012` в `ar` ↔ `s012` в `ru`). Сплит длинного: `s050a`, `s050b` склеиваются
  в базовый `s050`. Пустая строка завершает сектор.
- Страницы: `<!-- pN -->` **только в `ar/`**, протягиваются по id в `ru`.
- Сноски: `<!-- fnN -->` блоком в конце файла; ссылка в тексте — `[^N]` (только числа).
- Манифест `book.json`: `languages` (первый — оригинал/источник страниц), `rtl`,
  `chapters[{file,title}]`, опц. `author`, `description`, `hasImages`/`imagePattern`.
  Книга может быть **одноязычной** (`languages:["ru"]`).

### Каталог и классификация (`books/index.json` + `books/taxonomy.json`)

Полка/фильтры читают **реестр** (`index.json`) + **дерево разделов** (`taxonomy.json`).
Запись книги в `index.json`:
`{ id, base, title, kind?, date?, cover?, thumb?, category:"<id-узла>", tags:[], authors:[], madhhab:[], genre:[], langs:[], era?, review?, progress?, counts?, description? }`.
- `kind` — тип записи: `"article"` (статья) или книга (нет поля). `date` — день публикации
  статьи. `counts` и `description` — производные, пишет `tools/gen-meta.js`. Подробно — раздел
  «Книги и статьи» ниже.
- `thumb` — миниатюра обложки для полки (320 px, `cover-thumb.jpg` рядом с `cover.jpg`). Полка и
  список берут её, карточка книги — полную `cover`. **Добавил или заменил обложку — запусти
  `node tools/gen-thumbs.js`**: он создаст миниатюру и впишет `thumb` в реестр (нужен ImageMagick).
  Без миниатюры полка грузит полную обложку: девять книг весили 2 МБ вместо 250 КБ (14.11.2026).
  `tools/doctor.js` о пропущенной миниатюре напоминает.
- `category` — **id листового узла дерева** (строка, напр. `"aqida-iman-kufr"`), НЕ путь-массив
  (мигрировано 2026-06-20). Путь и цвет резолвятся обходом дерева по id (`bookCatPath`/`catColorOf`).
- **`books/taxonomy.json`** — дерево: плоский список `{ id, name, parent?, hue?, shade? }`.
  `hue` у L1 (цветовой род), `shade` у L2 (оттенок); глубже наследуется. До 4 уровней.
  Грузится за провайдером (`buildTaxonomy`), `catalogTree` = пути-массивы всех узлов.
- `review` (`approved`/`caution`) и `progress` (`ready`/`wip`) — две независимые оси
  доверия/готовности: бейджи на обложке (`applyBadges`/`APPROVAL`/`PROGRESS`) + фасеты.
- Фасеты (мультивыбор, ортогональны дереву, `FACETS` в `app.js`): `review`, `progress`,
  `langs`, `authors`, `madhhab`, `era`, `genre`, `tags`. Внутри группы ИЛИ, между И. Живут в
  **нижней панели** (`#filter-sheet`, кнопка-воронка).
- **Теги — формат (принят 18.10.2026, код — BACKLOG П7).** Тег — путь от общего
  к частному через `/`: `"фикх/намаз/фатиха"`, `"усуль/хукм/рукн"`. Строчными буквами,
  составное слово — через дефис (`иман-куфр`). Ветки те же, что у тегов `тема/…` базы знаний
  (`~/obsid/alqasawi/_claude/Инструкция.md`, «Словарь тегов»), только без `тема/`; лист
  может быть глубже, чем в базе. Тег подразумевает предков: `фикх/намаз` отдельно не
  писать, если есть `фикх/намаз/фатиха`. Теги ≠ раздел: `category` — одна полка, теги —
  сквозные темы. Старые плоские теги (`"тавиль"`) остаются валидными как теги верхнего
  уровня. Пока П7 не сделан, фасет «Тема» показывает путь целиком, а поиск по полке
  находит книгу по любому звену пути (подстрока).
- **Навигация = боковое дерево** (`#cat-tree`/`renderTree`), не чипсы. Десктоп — колонка,
  телефон — drawer по гамбургеру. Хлебная крошка над списком.
- **Три вида** (`settings.shelfView`): covers (деф.) / spines (корешки, цвет по категории,
  размеры по хэшу id) / list. `renderBookList`/`hashId`/`spineColor`/`spineDims`.
- Классификация задаётся вручную или формой публикации вычитки (пишет `category=id` из
  taxonomy); переживает переимпорт (`{...prev}`).

**Дерево разделов** живёт в `books/taxonomy.json` (правится свободно — это данные):
Акъида (Таухид · Иман и куфр) · Коран и его науки (Тафсир · Коранические науки) ·
Хадисы и его науки · Фикх и усуль (Усуль · Ибадат · Муамалят · Никах · Современные вопросы) ·
История и секты (Сира · Исламская история · Секты) · Языкознание и риторика · Зухд · Разное.

### Иерархия глав книги (`book.json.chapters`)

Главы могут быть деревом: у записи в `chapters` — поле **`level` (0–3)** и опц.
**`header:true`** (запись-группа без `file`, напр. `كتاب`, двуязычный `title{ar,ru}`).
Оглавление (`buildToc`/`renderTocList`) рисует дерево по `level` (отступы + сворачивание);
header-записи некликабельны, линейная навигация (`nextReadable`) их пропускает.
Нет `level` → 0 (плоско, обратная совместимость). Редактор иерархии — в вычитке
(режим книги: `book.json`; папка: `level` во фронтматтере + `outline.json`).

### ⚠️ Сноски — ПЕР-ЯЗЫЧНЫЕ (не откатывать!)

Сноски **не спариваются** между языками. У каждого языка свой список и своя нумерация;
ссылка `[^N]` ведёт к сноске `fnN` **того же языка** (в DOM id `fnN@lang`). Причина:
авторские сноски-цитаты (в `ar`) и пояснения переводчика (только в `ru`) — разной
природы и числа, спаривать их по номеру неверно. В `parser.js` сноски складываются как
одноязычные пары с тегом `lang`; в `app.js` клик/инлайн/скачок/поиск и видимость
учитывают язык. Если будущая задача — «почему сноски не парные», это **сделано
намеренно**, см. коммит «Сноски — пер-язычные».

### Целиком односторонняя глава

Если в главе у одного языка 0 текст-секторов (второй язык ещё не подключён) — это не
ошибка: валидатор даёт одну строку «глава целиком только в <lang>», а не шум по каждому
сектору. Полезно для недопереведённых книг.

- **Паритет** (равное число абзацев ar/ru) автор сводит в Вычитке. Ветка

### Как (пере)импортировать

```bash
git clone https://github.com/ismailovvism-oss/tawfiq-al-mannan.git /tmp/tam-book
cd /tmp/tam-book && git pull        # ветка split-paragraphs влита в main и удалена
cd <корень читалки>
node tools/import-tam.js /tmp/tam-book      # → books/tawfiq/{ar,ru}/ + book.json + index.json
node tools/validate.js books/tawfiq
```

Конвертер: именованные сноски (`[^ghuraba]`, `[^и1]`) → числовые `[^N]` + `<!-- fnN -->`;
вики-ссылки развёрнуты; нумерация сносок своя на каждый язык. **Заголовок не становится
отдельным сектором** — прицепляется к следующему текст-сектору как ведущая часть того же
`sNNN` (части `a`=заголовок, `b`=текст), иначе лишний блок сдвинул бы парность с арабским.
**Арабские строки двуязычных секторов** (аят `۞…`, арабский хадис) выкидываются из `ru/`
(остаются в `ar/`), иначе арабский виден дважды; сектор сохраняется. Маркеры страниц
мастера `<!-- ص: N -->` → `<!-- pN -->`; сканы страниц — в `books/tawfiq/img/` (`hasImages`).
**Арабский выдаётся только при точном посекторном паритете**; где ar≠ru — глава ru-only.

**Не редактировать руками** `books/tawfiq/**` — только регенерировать импортером. В
`source/` репозитория перевода НЕ писать (правило того проекта; там только автор/Вычитка).

## Разработка и деплой

- Разработка — в ветке сессии (`claude/...`); по готовности **fast-forward в `master`**
  (это «опубликованная» ветка). НЕ пушить в чужие ветки без явного разрешения.
- **Бампать `VERSION` в `sw.js`** при изменении файлов оболочки (`index.html`, `app.js`,
  `parser.js`, `style.css`, `translate.js`, `gloss.js`, `supabase/*.js`). ⚠️ С `v83` это
  ОБЯЗАТЕЛЬНО: оболочка отдаётся из кеша, не спрашивая сеть, и без нового номера читатель
  её не получит. Страховка есть (раз в 6 часов воркер сам сверяет оболочку с сервером), но
  это страховка, а не порядок. Текущий номер — в `sw.js` (на 16.11.2026 — `chitalka-v87`).
- **Деплой: GitHub Pages, автоматом на push в `master`** (2026-07-16; ушли с Netlify —
  там автодеплой был выключен из-за лимита кредитов и выкладка шла вручную build-hook’ом).
  Workflow — `.github/workflows/pages.yml`: сборки нет, репозиторий выкладывается как есть;
  перед выкладкой прогоняются `node --check` и `tools/validate.js` по всем книгам —
  **сломанный Контракт блокирует деплой**. Ручной запуск — вкладка Actions → Run workflow.
  Адрес: `https://ismailovvism-oss.github.io/biblioteka-tawhid/`.
  - **`.nojekyll` в корне трогать нельзя** — без него Jekyll выкидывает пути с `_`
    (`books/_sample/`, `books/_sample-en/`), и эталонные книги пропадают с прода.
  - Воркер с `v83` отдаёт сохранённое сразу, а свежее тянет следом — см. раздел «Воркер
    и кеш». Урок `v57` при этом остаётся в силе: к своему серверу воркер обращается только
    с `cache: 'no-cache'` (условный запрос, обычно 304) или `'reload'`. Без этого браузер
    по своей эвристике отдавал старую копию, минуя сеть: книга получила `"gloss"` в
    манифесте, а приложение месяцами видело бы манифест без него, без единой ошибки.
- ⚠️ **Репозиторий разрабатывается с двух устройств параллельно.** ВСЕГДА `git fetch` +
  работа поверх свежего `origin/master` перед пушем; никогда не force-push. `master`
  «опубликованный». Бренд — **«Библиотека Таухид»**.
- Репозиторий — `ismailovvism-oss/biblioteka-tawhid` (переименован из `chitalka-parallel`
  16.07.2026). Локальная папка может по-прежнему называться `chitalka-parallel` — это
  косметика, на remote не влияет. Имя кеша SW (`chitalka-vNN`) — внутренний ключ, не имя репо.
- `parser.js` держать Node-совместимым (без DOM) — на нём валидатор.
- Проверять синтаксис: `node --check app.js && node --check parser.js`.

## Воркер и кеш: запуск с устройства (2026-11-15, sw `v83`)

До `v83` воркер для всего шёл «сначала в сеть», и скорость читалки равнялась скорости
сети, даже когда всё нужное лежало на устройстве. 15.11.2026 хостинг закрыл наш адрес, и
установленная читалка **136 секунд показывала пустой экран**: сервер принял соединение и
молчал, запросы не падали, а висели. Теперь у кеша три полки (`sw.js`):

- **Оболочка** (`SHELL_CORE` + `SHELL_EXTRA`, кеш `chitalka-shell-vNN`) — с устройства,
  сеть не ждём. Ставится целиком при установке воркера; обновляется новой версией воркера.
- **Содержимое** (`books/**`, `books-private/**`, кеш `chitalka-content-v1`) — сохранённое
  отдаём сразу, свежее тянем следом. Изменилось — воркер шлёт странице `updated`:
  реестр и дерево разделов → полка сама перерисовывается на месте (`reloadRegistry`);
  текст открытой записи → сообщение «Текст обновился · Показать» (`onSwMessage`).
  Молча подменять текст под читающим нельзя: абзац, уехавший из-под глаз, хуже опечатки.
- **Шрифты** Google (кеш `chitalka-fonts-v1`) — с устройства. Для этого у `<link>` таблицы
  шрифтов стоит `crossorigin`: без него ответ «непрозрачный», и в кеш его не положить.
- Остальное со своего адреса и то, что страница просит свежим (`cache: 'no-cache'`), —
  «сначала сеть», но при запасной копии ждём сеть не дольше 4 секунд.
- **Чужие адреса идут мимо воркера** (переводчик MyMemory, бэкенд, внешние картинки): в
  адресе запроса к переводчику — сам переводимый текст, в кеше ему не место. Появятся книги
  с содержимым на чужом адресе — завести для них явное правило.

Что из этого следует:

- ⚠️ **В кеш содержимого не идёт страница вместо не-страницы** (`plausible`). Хостинг в беде
  отвечает «200 OK» заглушкой на любой адрес; без этой проверки заглушка затёрла бы реестр
  и главы — ровно тогда, когда на сохранённое вся надежда. У оболочки проверка строже
  (`looksRight`). Добавляешь новый путь записи в кеш — проверяй ответ так же.

- ⚠️ **Не возвращать «сначала сеть» для оболочки и книг.** Правка текста доходит до читателя,
  уже открывавшего главу, на одно открытие позже — это цена, и она заплачена сознательно.
- ⚠️ **Реестр (`books/index.json`) в оболочку не класть.** Он — содержимое: меняется без
  подъёма `VERSION`. В оболочке он застыл бы до следующей версии.
- ⚠️ **Чужие кеши не удалять.** У Cache Storage граница — сайт, а не папка: на `tawhiid.com`
  и на `github.io` рядом живут другие приложения. Воркер чистит только `chitalka-*`.
- **Первый показ не ждёт сеть.** `init` не дожидается непубличных книг (`refreshLibrary`
  идёт следом и перерисовывает полку, если состав изменился); ждёт их только тогда, когда
  в адресе запись, которой нет в публичном реестре. `fetchText` обрывает запрос через
  30 секунд; дольше четверти секунды ждём — показывается полоса загрузки (`body[data-busy]`).
- **На `localhost` воркер работает по-старому, «сначала сеть»** (`DEV` в `sw.js`): там
  читалку правят, и кеш прятал бы каждую правку. **Кеш и скорость проверять по адресу
  `127.0.0.1`** — для браузера это другой сайт, со своим воркером.
- **Отключённая сеть ≠ молчащий сервер.** Без сети запрос падает сразу, и беды не видно.
  Проверять `node tools/stend.js` → `http://127.0.0.1:8131/`, режим `/__stend?mode=hang`
  (там же счётчик запросов: `/__stend`; режим `stub` — хостинг отвечает заглушкой с кодом 200). Замеры 15.11: запуск — 15 запросов → 0 к оболочке;
  при молчащем сервере полка появляется за сотые доли секунды.
- Поменял оболочку и не видишь правки на `127.0.0.1` — так и должно быть: подними `VERSION`
  либо сними отметку сверки (`__shell-checked` в кеше оболочки) и открой страницу заново.
- **Ссылка на только что опубликованную запись.** Сохранённый реестр о ней ещё не знает.
  Поэтому `init`, не найдя запись из адреса, перечитывает реестр свежим (и ждёт непубличные
  книги), но не дольше полутора секунд; не уложились — показывает полку и открывает запись сама,
  когда та появится (`wantedMiss`, `retryWanted`). Не убирать: по таким ссылкам приходят
  из Telegram.
- **«Показать» и «Обновить» перезагружают страницу, сохранив место** (`reloadKeepingPlace`):
  адрес сокращается до `?book=<id>`, иначе читатель вернулся бы к месту из чужой ссылки.
- **Сообщение о новой оболочке шлёт воркер** (`shell-updated`): из `activate`, когда удалил
  прежний кеш оболочки, и из страховочной сверки. По смене воркера (`controllerchange`) об
  этом судить нельзя — при переходе с `v82` страница уже приходила новой.
- Прежний единый кеш (`chitalka-vNN`) разбирается по полкам в фоне, по одной записи
  (`adoptLegacy`): в `activate` это держало бы запросы страницы.

**Поиск по библиотеке берёт книгу одним файлом** — `books/<id>/search.json` (SPEC 3.7).
Раньше он скачивал и разбирал все главы всех книг: 239 запросов на первом поиске (эту
очередь хостинг и принял за атаку), а каждый следующий заново приводил весь текст к виду
для сравнения. Теперь 11 запросов и 2–40 мс на поиск, поэтому он идёт по мере набора.

- Файл собирает `tools/gen-search.js` (зовётся из `gen-meta.js`); устарел или пропал —
  скажет `doctor.js`. Сборка — в `parser.js` (`searchIndex`, `htmlPlain`), одна на
  инструмент и на читалку.
- ⚠️ **`htmlPlain` обязана давать ту же строку, что `textContent` в браузере**: по смещениям
  в ней поиск красит найденное в отрисованной главе. Сверено на всей библиотеке (4236
  секторов, расхождений 0). Меняешь разметку в `parser.js` — пересверь.
- ⚠️ **`normalize` и `normalizeWithMap` обязаны давать одну строку**: сравниваем по первой,
  смещения переводим картой второй.
- Нет файла (книга опубликована мимо инструмента — например, из Вычитки, которая его пока
  не пишет; непубличная из бакета) — читалка собирает то же из глав, по-старому медленно.
- **Отставший файл читалка узнаёт сама.** В файле лежит `c` — число глав и слов; в реестре
  то же число в `counts` (один счёт, `contract.js`). Не сошлось — файл собран по другому
  тексту, книга читается по главам. Правку, не меняющую числа, ловит `hitOffsets`: при
  переходе к найденному сектор сверяется с живым текстом, и смещения пересчитываются.
- ⚠️ **По главам — только когда файла нет или он негоден** (404, не разобрался, отстал).
  Сервер отказал (429, 5xx) или молчит — книга считается незагруженной, выдача честно
  говорит «не загрузилось книг: N». Иначе больному серверу досталась бы очередь из
  десятков запросов на книгу — та самая, за которую хостинг закрывает адрес.
- Выдача рисуется по мере прихода книг (`runSearch`, `scanBooks`): одна застрявшая не
  держит остальные.

**Полка помнит место** (`shelfReturn`, `leaveShelf`): ушли в книгу и вернулись — стоим там
же. Только на возврат: смена вкладки, раздела, фильтра показывает новый список сверху.

## Книги и статьи (2026-11-14, SPEC 3.6)

Запись реестра бывает **книгой** или **статьёй**: `"kind": "article"` в `books/index.json`,
нет поля — книга. Движок и формат текста одни (Контракт), различается только подача.
Критерий: статья отвечает на один вопрос и читается за один присест; книга — много тем и
главы, которые читают по отдельности. Статьи сейчас — `posuda`, `libas`, `muha`, `fatiha`,
`tavil`; комиксы `arab-paltsy` и `tafsir-fatiha` решением автора пока книги (третий тип
«уроки» можно добавить позже — это новое значение `kind`, а не переделка).

- **Обложка есть у обоих** — это пожелание автора. Различие делает подача: книга стоит
  обложкой на деревянной полке, статья — карточкой в ленте, где обложка маленькая и
  плоская, а главное — заголовок и аннотация. ⚠️ Не «различать» типы отсутствием обложки.
- **id и адреса от типа не зависят**: `?book=<id>` открывает и книгу, и статью. Сменить
  тип записи можно в любой момент — ссылки из Telegram живут. Статьи **не переносить** в
  базу знаний `/ilm` (Quartz): им нужны сноски, арабский рядом, шарх и кадры читалки.
- **Полка** (`renderLibrary`): вкладки «Книги / Статьи» (`settings.shelfKind`, `KINDS`,
  `shelfKind()`); книги — три прежних вида, статьи — лента (`articleItem`, вид `feed`),
  рисуется теми же порциями по 60 (`renderBookList`). Порядок помнится порознь: книги —
  `settings.shelfSort` («как в реестре»), статьи — `settings.shelfSortArticles` («сначала
  новые», по `date`). Дерево разделов и фильтры считают записи открытой вкладки.
- **Статья открывается сразу в текст** (`openEntry`), карточки книги у неё нет; старая
  ссылка `?info=<id>` на статью уводится на `?book=<id>` (`route`). Что показала бы
  карточка — в шапке статьи (`articleHead`): название, автор, дата, время чтения, отметка
  одобрения, аннотация и небольшая обложка сбоку.
- **Статья читается одной страницей** (`singlePage`, `loadArticle`): все главы грузятся
  разом и ложатся в один поток как разделы с заголовками (`sectionHead`), сноски всей
  статьи — одним списком в конце, после «Конец статьи». «Перейти к главе» в статье —
  прокрутка к разделу, не перерисовка; стрелок глав, свайпа и ←/→ нет.
  `chapterIndex` в статье — раздел абзаца у центра экрана (`followSection`).
- ⚠️ **В потоке статьи лежат ВСЕ главы, а `s003` и `fn1` есть в каждой.** Искать место по
  одному id нельзя — найдётся первый раздел с таким сектором, то есть чужой абзац.
  Только «глава + id»: `pairAt(глава, id)`, `pairsOf(глава)`, `chapterOf(элемент)`,
  `inStream()`. `pairById` поэтому убран. Глобальный `pairs` — глава у центра экрана;
  для данных конкретного абзаца брать `pairsOf(chapterOf(el))`.
- **Сноски статьи нумеруются сквозно** (`numberFootnotes`, `fnNumber`, `showFnNumbers`):
  в файлах счёт у каждой главы свой, а показывается номер по порядку во всей статье.
  В `data-fn` — номер из файла, в тексте кнопки — показанный. ⚠️ Отсюда `shownOffsets`:
  поиск считает место попадания по данным, а красим показанный текст, где «3» могло
  стать «12» — без поправки подсветка съезжает. Пометки сняты с показанного текста и при
  смене типа записи перепривязываются сверкой по снимку (`сверитьПометки`).
- **Прогресс статьи** — доля прокрутки до КОНЦА ТЕКСТА (`.art-end`), а не страницы: ниже
  лежат сноски (у «Фатихи» это половина объёма). Доля пишется в `last.pct`; лента
  показывает «читаю · 40%» / «прочитано», дочитанная статья открывается сначала.
- **Время чтения** — `counts.words / 200` слов в минуту (`readTime`), сноски в счёт слов
  не идут. **Подпись типа** (`kindLabel`: «Статья · 14 мин», «Книга · 37 глав») стоит там,
  где типы вперемешку: поиск по библиотеке, «Продолжить», вырезки.
- **Добавил статью или поправил её текст — `node tools/gen-meta.js`**: он пересчитает
  главы и слова и скопирует аннотацию из `book.json` в реестр (карточке ленты она нужна
  до открытия статьи, а тянуть манифест на каждую карточку нельзя). `doctor.js` скажет,
  если сведения устарели, тип неизвестен или у статьи нет даты. Конвертер статей
  `~/projects/tools/statya/в-читалку.py` сам ставит `kind`, `date` и зовёт `gen-meta.js`.
- ⚠️ **Прокрутка сразу после закрытия панели** (раздел из оглавления, пометка, попадание
  поиска в том же потоке) идёт через `settleBack()`: панель закрывается шагом назад по
  истории, он происходит чуть позже и обрывает начатую плавную прокрутку. Там же причина
  `history.scrollRestoration = 'manual'`.
- `leaveReading()` сбрасывает `bookId` при уходе на полку: раньше он переживал уход, и
  поиск с полки открывался в границах последней книги.
- ⚠️ Проверять прокрутку — только при видимой панели браузера: в скрытой плавная прокрутка
  не идёт вовсе, и кажется, что переход к разделу сломан (14.11.2026 на этом потеряно время).

## Полка и статья: что читал, что новое, что дальше (2026-11-15)

Вторая волна разбора пятнадцати программ (первая — «Воркер и кеш»). Всё в `app.js`.

- **Состояние чтения выводится, а не отмечается** (`readState` → `stateOf`, `readPct`,
  `doneAt`): из `settings.last`. ⚠️ Кнопку «отметить прочитанным» не заводить: Литрес ругают именно за
  ручную отметку. Три состояния:
  - *не читал* — в записи нет времени (`ts`). ⚠️ Открыл и ушёл — тоже «не читал»:
    `rememberPosition` не пишет время и долю, пока читатель стоит у самого начала (не
    прокрутил на полэкрана, не ушёл дальше первой главы, не увидел конец). Иначе ряд
    «Продолжить» забивается открытым на секунду с подписью «0%»;
  - *дочитал* — на экран поднялся конец текста (`atEnd` в `updateProgress`): у статьи это
    доля от 97 (`READ_DONE`), у книги — надпись «Конец книги» под последней главой.
    ⚠️ У книги по доле не судить: она идёт по главам, и в книге из 37 глав 97% набегают
    на пороге последней. ⚠️ И по одной надписи не судить: у короткой последней главы
    (приложение, указатель) она видна сразу, и заход из оглавления сделал бы книгу
    прочитанной — конец засчитывается, если в главу пришли по порядку (`inOrder`, ставит
    `loadChapter`) либо долистали её дальше полэкрана. Отметка `done` в записи ставится
    один раз и не снимается — вернулись перечитать главу, а книга осталась прочитанной
    (отдельной кнопки «снять» нет, поэтому ложная отметка дорога);
  - *читаю* — всё остальное. Доля (`pct`) с `v85` пишется и у книг; у комикса её, время и
    `done` пишет `comicRender` (кадры прокрутки не дают, прокрутка текста под комиксом
    «дочитано» не ставит).
  Записи, сохранённые до `v85` (без `done`), писались при каждом открытии, и «открыл и
  ушёл» в них от «читаю» не отличить — `stateOf` судит по месту: статья с долей от 97 —
  дочитана, с нулевой — «не читал»; книга на первых абзацах первой главы — «не читал».
- ⚠️ **`rememberPosition` пишет, только если в потоке текст этой записи** (`streamOf`).
  Пока открывается следующая запись, на экране ещё стоит прежняя, и её место вместе с её
  «дочитано» записалось бы под чужим id — статья из «Что читать дальше» стала бы
  прочитанной, не будучи открытой.
- **Ряд «Продолжить»** (`continueRow`) — начатое и не дочитанное, свежее первым, не больше
  восьми (`CONT_MAX`). **Чипы** (`drawChips` в `renderLibrary`; `statusOk`, `lenOk`) —
  состояние и длина. Живут в переменных `shelfStatus` / `shelfLen`, ⚠️ намеренно не в
  `settings` — по той же причине, что запрос на полке, — и только на своей вкладке
  (`shelfChipsOf`): на другую попадают не одной её кнопкой. Число на чипе — сколько записей
  окажется в списке по нажатию: считается по тому же списку (раздел, фильтры, запрос), с
  учётом соседней группы чипов и без своей, поэтому ряд перерисовывается вместе со списком
  (`paint`). Чип, который ничего не отбирает, не рисуется.
- **Разделы чипами** (`.sec-chips`) — только на узком экране; на широком их прячет стиль,
  там дерево слева. Крошка «Все …» на узком экране в корне скрыта. Выбран подраздел — чип
  его раздела подсвечен и ведёт к разделу, а не сбрасывает выбор.
- **«Новое»** (`isNew`): статья с `date` не старше 30 дней и без записи в `settings.last`
  (открытая статья «новой» быть перестаёт, даже если её не читали).
- **«Начните отсюда»** (`pinnedBlock`) и **серии** (`seriesOf`) — поля реестра `pinned`,
  `series`, `part` (SPEC 3.6). Ставит автор руками; `doctor.js` проверяет. «Из скольких
  частей» — по старшему номеру и с черновиками, не по числу выложенных записей.
- **«Содержание»** (`articleToc`) стоит в шапке статьи; **«Что читать дальше»**
  (`articleNext`) — отдельным блоком ПОСЛЕ `.art-end`. ⚠️ Внутрь `.art-end` не класть: по
  его низу считается доля прочитанного, и статья «дочитывалась» бы позже.
- **Шапка в чтении на узком экране** — название раздела своей строкой под значками;
  нажатие на название (на любом экране) открывает оглавление — когда оглавление этой записи
  построено (класс `toc-ready` на `body`). ⚠️ Высоту шапки не подгонять числом: её меряет
  `app.js` в переменную `--topbar-h` (при крупном шрифте значки занимают две строки, и
  название становится третьей), отступ текста и цели переходов в `style.css` берут её оттуда.
- В рядах, которые листаются вбок (`.cont-row`, чипы), полоса прокрутки скрыта только на
  сенсорном экране: с мышью ряд иначе не пролистать (`@media (hover: hover) and (pointer: fine)`).

## Навигация: один поиск, оглавление на карточке, адрес полки (2026-11-15)

Третья волна разбора пятнадцати программ. Код — в `app.js`, оформление — последний блок
`style.css`.

- **Один поиск** (`runSearch` → `renderResults`): три группы по порядку — записи по
  названию (`titleHits`, из реестра, сразу), главы и разделы по названию (`chapterHits`, из
  тех же поисковых файлов, что и текст), места в тексте. ⚠️ Группы названий не убирать под
  текст и не смешивать с ним: ищут чаще вещь, чем место. Поле на полке осталось (оно
  отбирает список на месте, вместе с чипами и фильтрами); из него в общий поиск ведёт
  кнопка `.shelf-intext` → `openSearch(запрос)`.
  - Слово запроса из одной-двух букв засчитывается только целиком, как и в тексте
    (`подходит`): частью слова «на» нашлось бы в каждой записи.
  - Раскрытая группа («Ещё N») помнится, пока запрос тот же (`searchOpened`): выдача
    перерисовывается по мере прихода книг, и строка не должна уезжать из-под пальца.
  - Известные пределы: глава ищется по одному названию — тому же, что стоит в поисковом
    файле (русскому, если оно есть; арабское название двуязычной главы не найдётся); глава
    без текста (одни картинки) в поисковый файл не попадает.
- **Оглавление на карточке книги** (`bookInfoToc` в `renderBookInfo`): по `chapters`
  манифеста, уровни — отступом, записи без файла — подзаголовками. Текущая глава — по
  `settings.last`, и только если читатель действительно читал (`stateOf`). ⚠️ Свёрнутое
  оглавление не должно прятать главу «вы здесь». Глава с карточки (и из поиска) у
  книги-комикса открывается кадрами, как и по «Читать» (`openBook`, ветка `opts.chapter`).
- **Адрес полки** (`shelfUrl`, `applyShelfUrl`, `writeShelfUrl`; формат — SPEC 5.9).
  Состояние полки по-прежнему лежит в `settings` и переменных (`shelfQuery`, чипы); адрес —
  его отражение, чтобы им можно было поделиться.
  - Пишем через `replaceState`, только отличное от обычного; читаем в `route()`. Порядка
    и вида списка в адресе нет: это привычка читателя, чужая ссылка не должна её менять.
  - ⚠️ Чистый адрес ПРИ ЗАПУСКЕ — «полка, какой её оставили»; любой параметр полки — адрес
    задаёт её целиком. Не менять на «чистый адрес = сброс»: у установленной читалки адрес
    запуска чистый, и вкладка с разделом слетали бы при каждом открытии. А на шаге по
    истории (`route(true)` из `popstate`) чистый адрес — «полка без отбора»: адрес каждой
    записи истории мы сами держим в актуальном виде.
  - ⚠️ Слепок полки для возврата прокрутки (`shelfSig`) берёт фильтры в каноническом виде
    (`facetsCanon`): тот же отбор, собранный из адреса и лежащий в `settings`, обязан давать
    одну строку, иначе возврат из книги теряет место.
  - ⚠️ **Когда уходит маркер панели** (`popstate` после закрытия оверлея), экран главнее
    адреса: под маркером лежит адрес на момент открытия панели, и читать его — значит
    откатить то, что в панели выбрали. Поэтому там `writeShelfUrl()`, а не `route()`.
    По той же причине каждая кнопка, закрывающая панель, обязана звать
    `consumeOverlayMark()` (у «Применить» в фильтрах его не было).
  - Пока на полке стоим вместо записи из адреса (`wantedMiss`), адрес не трогаем — он
    нужен `retryWanted`. Читатель сам ушёл с полки или «домой» — запись больше не ждём.
  - ⚠️ **Новый шаг истории — только через `navPush(url)`**, не голым `history.pushState`.
    Адрес полки из `paint` пишется с задержкой (`writeShelfUrlSoon`, 400 мс: Safari даёт
    менять адрес не чаще ста раз за полминуты, а набор запроса — правка на каждую паузу);
    `navPush` сперва дописывает отложенное в запись полки, иначе оно легло бы в запись
    книги, а «назад» вернул бы полку со старым запросом. Маркер панели (`openOverlay`)
    делает то же через `flushShelfUrl`.
  - Шаг «вперёд» на маркер закрытой панели ничего не делает: читалка сразу возвращается на
    запись полки (иначе в истории было бы две записи одной полки с разными адресами).
  - Раздел, которого нет в `taxonomy.json` (переименовали; дерево не загрузилось), адресом
    не выразить — `applyShelfUrl` его не сбрасывает.

## Автозаполнение браузера — не в наши поля (2026-11-15)

Браузер, сохранивший для сайта почту, сам вписывает её в текстовое поле, которое сочтёт
«логином», — в том числе в скрытое. Дважды это выглядело как поломка читалки: полка
«пустела» (поле поиска на полке; с тех пор оно создаётся только по нажатию), а в Edge на
телефоне оглавление отвечало «Глав по запросу "почта" нет».

- ⚠️ **Каждое своё текстовое поле — через `guardAutofill`** (`app.js`). У поля есть «своё
  значение» — то, что набрал читатель, пока поле было в фокусе, или положил код
  (присваивание `поле.value = …` перехвачено). Событие `input` в поле без фокуса — не от
  читателя: полю возвращается своё значение, до обработчиков событие не доходит. При
  открытии панели (`openOverlay` → `restoreOwn`) её поля приводятся к своему значению — на
  случай, когда браузер заполнил поле молча, без события. Заводишь новое поле поиска или
  фильтра — добавь его в список рядом с `guardAutofill`.
- ⚠️ **Судить только `input`, не `change`.** `change` приходит, когда читатель уходит из
  поля, и фокуса на поле в этот миг уже нет. Первая версия защиты мерила оба события одной
  меркой и стирала набранное при первом касании мимо поля — запрос поиска, теги пометки,
  название промпта. Поймано независимой проверкой до выкладки. Проверять защиту — обоими
  способами: и подстановку, и настоящий набор с уходом из поля.
- Не защищены намеренно: `#acc-email` (это и есть поле входа, почта там по делу) и
  многострочные поля (`textarea`) — их браузер не заполняет.
- ⚠️ **Не заводить `type="password"`** без нужды: с ним браузер считает страницу формой
  входа и начинает подставлять «логин» куда попало. Ключ OpenRouter — `type="text"` со
  стилем `.secret` (`-webkit-text-security`). В браузерах, не знающих этого свойства
  (Firefox до 114, середина 2023), ключ виден открытым текстом — осознанная цена: свой ключ
  на своём устройстве против полей, в которые браузер пишет сам.
- Проверка без Edge, в консоли: (1) вписать значение в поле и послать событие `input`, не
  ставя фокус, — поле должно вернуться к прежнему значению; (2) поставить фокус, набрать
  текст, щёлкнуть мимо — текст должен остаться.

## Значки интерфейса — SVG, не эмодзи (2026-11-14)

Значки кнопок и бейджей — линейные SVG одного стиля: спрайт `<symbol id="i-имя">` в начале
`index.html`, в разметке `<svg class="ico"><use href="#i-имя"/></svg>`, в коде —

- ⚠️ **Не возвращать эмодзи в интерфейс** (📚 🔍 ⚙ 🗑 …): каждый телефон рисует их по-своему —

  добавь `<symbol>` в спрайт (сетка 24×24, только геометрия, без `stroke`/`fill`).

- Типографские знаки (`✕ ‹ › ← →`) оставлены текстом: они из шрифта и выглядят одинаково.

  ужаты, иначе на телефоне название главы сжимается до «Во…».

## Форматирование, заметки и недопереведённые секторы (2026-06-16)

Общий **словарь форматирования с вычиткой** (она — редактор этого формата). `parser.js`:
- `inlineMd` понимает `<u>подчёркивание</u>` (помимо `**жирный**`, `*курсив*`, `[^N]`);
- `renderGroup`→`renderBlocks` рисует блочный markdown внутри сектора: цитата `> ` →
  `<blockquote>`, списки `- `/`1. ` → `<ul>/<ol>`, callout Obsidian `> [!тип] заголовок`
  → `.callout.callout-<тип>` (тип произвольный; без заголовка — подпись из `CALLOUT_LABELS`).
  `[!тип]+`/`[!тип]-` — сворачиваемый callout (`<details class="callout-foldable">`,
  `+` раскрыт / `-` свёрнут; тело свёрнутого скрыто явным CSS, не UA-стилем).
- `parseFile` **прячет регионы `<!-- note --> … <!-- /note -->`** — это личные
  редакторские заметки автора (вычитка), не для публикации.
- **Иллюстрации** (2026-07-16, SPEC 3.4a): строка целиком из `![подпись](media/схема.png)`
  → `<figure>`; тап → тот же полноэкранный просмотр, что у сканов (`showImage`).
  **Своя на каждый язык** (секторы пер-язычные), один файл — одна ссылка в обоих.
  Папка `media/`, НЕ `img/` (там сканы страниц). Путь резолвится от базы книги —
  `buildChapter(texts, langs, { base })`. Небезопасные пути (`javascript:`, `..`,
  внешний URL) не рендерятся + предупреждение; инлайн внутри абзаца намеренно не
  поддержан. Валидатор проверяет существование файла → битая ссылка валит CI.
  Пример — `books/_sample/`, сектор `s007` (одна схема, подписи ar и ru разные).
- **Листалка** (2026-10-18, SPEC 3.4d): `> [!slides] Заголовок` + строки `> ![подпись](media/…)`
  → кадры, листаемые как альбом Telegram / визуальный тафсир `apps/tafsir-app`.
  Разметка — `renderSlides` в `parser.js`; поведение — блок «ЛИСТАЛКА» в `app.js`.
  Лента — родная горизонтальная прокрутка со `scroll-snap` (свайп нативный), номер кадра
  **не хранится**, а считается из `scrollLeft` (`slidesIndex`) — переживает перерисовку.
  Высота ленты = высота текущего кадра (`slidesSync`, по `scroll` и `load` на погружении).
  Свайп глав в `touchstart` пропускает `.slides`; ←/→ и Esc перехватываются на погружении.
  «Во весь экран» — класс `.sl-full-on` (`position: fixed`), не Fullscreen API.
  **Режим «комикс»** (SPEC 3.4e): `"view": "comic"` в book.json; блок «КОМИКС» в `app.js`
  (`comicFrames` строит кадры из отрисованной главы, `#comic` — свой оверлей, учтён в
  `anyPopupOpen`/`closeTopPopup`). Проверять на Android: Waydroid + Chrome, отладка через
  `adb forward tcp:9333 localabstract:chrome_devtools_remote`; страницу отдавать на
  `192.168.240.1` (адрес хоста в сети Waydroid).
  Из статьи в книгу кадры несут конвертеры `tools/statya` (`в-вольт.py` → `в-читалку.py`,
  файлы → `books/<id>/media/`); как рисовать кадры — скилл `statya`, §7.1.

  полка = статический `books/index.json` ∪ доступные непубличные (`refreshLibrary`). Бэкенд

  каталог в базу **не переносить**.
- **В коде:** `supabase/client.js` — клиент на голом `fetch` → `window.SB` (без сборки и
  зависимостей); в `app.js` — `renderAccount` (вход/выход), `refreshLibrary`/`loadPrivateBooks`

  иначе токен-гейт обходится через кеш.

- **Вход: «Signups not allowed for otp» = почта не заведена, а не поломка.** Публичная

- ⚠️ **Redirect URLs**: возврат по магик-ссылке идёт на `location.origin + pathname`, и
  этот адрес должен быть в списке проекта. В списке — Pages и `localhost:8000`; если
  поднять локальный сервер на другом порту, вход вернёт на Site URL (Pages), а не назад.
  Локально это обычно и не нужно: непубличные книги читаются из `books-private/`.
- **Непубличные книги — в `books-private/<id>/`**: папка внутри проекта, целиком под

  `books-private/index.json` **генерируется**: `node tools/private-index.js`.
  Подробности и почему не GitHub/R2 — в `BACKEND.md`.
- **Два пути чтения непубличной книги, и это намеренно.** Локальная копия (`local: true`,

  доступна с других устройств. Одна книга обычно есть в обоих местах; `refreshLibrary`

## Пометки, вырезки, сборники (2026-08-07)

**Одна сущность на всё** — `settings.marks[bookId]`, запись:
`{ id, chapter, sector, lang, start, end, color, note, tags[], text, page, ts, edited }`.
Различаются заполненностью полей, а не типом:
- `start === null` → **закладка** (якорь на весь сектор, места в тексте нет);
- `start !== null` → **выделение**; с `note` — **заметка**; всякая с диапазоном — **вырезка**.

⚠️ **Не разносить обратно на два механизма.** До этого были `bookmarks` (умели заметку, но
не знали фрагмента) и `highlights` (знали фрагмент, но заметку прицепить некуда) — и
главного, «выделил кусок и записал мысль», не умел ни один. `migrateMarks()` переносит
старые ключи один раз при старте и чистит их **после** переноса.

- **`text` — снимок фрагмента, и это намеренно.** Вырезка обязана читаться без книги (общий
  список, сборник, выгрузка): книга бывает приватной без сети, переимпортированной (смещения
  уехали) или удалённой. Якорь — чтобы «перейти», снимок — чтобы читать. Не «оптимизировать»,
  вычисляя текст по якорю.
- **Тап по выделению открывает правку, а не удаляет** (`openMarkEditor`). Раньше удалял —
  случайным касанием терялась мысль.
- Цвета: полупрозрачные `--mk-*` в тексте (читаются на светлой/сепии/тёмной), плотные
  `--mkb-*` на гранях списка и кружках палитры. ⚠️ `#sel-toolbar button` — селектор с id,
  он перебивает `.sw-*`; поэтому там стоит `:not(.swatch)`.
- **Вырезки (`✂`) — сквозной раздел по всем книгам** (`allMarks`, `renderClips`), не вкладка
  внутри книги: тема почти всегда собирается из разных книг. Фильтры — книга/тег/цвет + поиск.
- **Сборники** (`settings.collections`) — тематические подборки, ссылки `{book, mark}`;
  копируются как markdown. Мёртвые ссылки (пометку удалили) просто не рисуются, а `removeMark`
  их вычищает.
- `renderClips()` молчит, пока панель скрыта — открывать надо **до** отрисовки.

## Полка под тысячи книг (2026-08-07)

Каталог рассчитан на тысячи записей, и полка сделана под это, а не под текущий десяток.

- **Список рисуется порциями по 60** (`renderBookList` → `pump`), остальное досыпается при
  прокрутке — это касается и ленты статей (проверено на 3000 статей: первая порция 60,
  отрисовка 58 мс). ⚠️ **Не возвращать «отрисовать всё разом»** — на 3000 книг вкладка вешается
  насмерть (проверено на синтетическом реестре). И **не заменять досыпку синхронным циклом**
  «пока маячок выше сгиба»: такой цикл меряет раскладку на каждой итерации и в пределе
  рисует весь список — тот же результат.
- Досыпка: `IntersectionObserver` + **синхронная переподписка** (`unobserve`+`observe`).
  Наблюдатель сообщает об ИЗМЕНЕНИИ пересечения; без переподписки список замирает на первых
  60, если одной порции не хватило до низа экрана. Плюс запасной путь через `scroll` — в
  фоновой вкладке ни кадры, ни IO не выдаются, а в части webview IO придушен.
- **Поиск на полке** (`entryMatchesQuery`) — по названиям всех языков, авторам, тегам,
  жанру, мазхабу, пути раздела; нормализация общая с поиском по тексту (`normalize`), кэш
  строки поиска — в `haystackCache` (WeakMap), иначе пересборка на каждое нажатие.
  Запрос живёт в `shelfQuery`, **намеренно не в `settings`**: восстановленный при следующем
  запуске фильтр читается как «библиотека опустела».
- **Порядок** — `settings.shelfSort`, по умолчанию `manual` (порядок реестра = авторская
  расстановка, её нельзя молча ломать).
- Панель полки строится один раз, при вводе перерисовывается **только список** (`paint`) —
  иначе поле поиска пересоздаётся на каждой букве и теряет фокус.
- **Счётчики фасетов** считаются по книгам, прошедшим все ОСТАЛЬНЫЕ группы; своя группа
  исключена (внутри неё ИЛИ), выбранное значение показывается даже с нулём — иначе его
  нечем снять.
- **Фильтр оглавления** (`#toc-filter`, от 12 глав): при вводе дерево разворачивается в
  плоский список, путь группы — подписью. Совпадение по пути учитывается.

Остальное из разбора интерфейса (авторы как ось, алфавит, серии, «моя полка», сохранённые
фильтры, аннотации на полях) — в `BACKLOG.md`.

## Машинный перевод (2026-08-07)

Вспомогательный слой, **не часть книги**. `translate.js` — только получение перевода;
показывает его `app.js` отдельной карточкой поверх текста.

⚠️ **Машинный перевод не попадает в поток секторов. Никогда.** Рядом стоит выверенный
человеческий перевод, и на кораническом/хадисном арабском машина регулярно даёт
доктринально неверное — слитые визуально, они неразличимы. Единственный мостик в книгу —
кнопка «в заметку», и она подписывает текст как машинный.

**Но показывается он ПОД абзацем, а не всплывашкой** (`placeMtCard`, класс `.mt-inline`):
так перевод виден вместе с исходником и ничего не заслоняет. Это не противоречит правилу
выше: карточка стоит *между* парами, а не внутри пары, её отделяют плашка «⚡ машинный
перевод» и акцентная грань, и она исчезает при закрытии и при смене главы. Ничего не
сохраняется. Границу держать: внутрь `.member` этот текст не класть.
- ⚠️ `detachMtCard()` обязателен ПЕРЕД `renderChapter` — тот чистит `stream` через
  `innerHTML`, и карточка вместе со всеми обработчиками была бы уничтожена насовсем.
- Карточка встаёт после развёрнутых сносок абзаца, а не между ним и ими: `toggleInlineFn`
  ищет свою сноску, шагая по соседям до первого не-`.fn-inline`.

- **`mymemory`** — бесплатный, без ключа, CORS открыт → зовём прямо из браузера.
  Лимит **500 БАЙТ** на запрос (не символов: кириллица и арабский многобайтовые),
  поэтому `splitForMyMemory` режет по предложениям → по словам → посимвольно.
  Последняя ступень не декоративная: длинный URL или склеенный идентификатор иначе
  уходит одним куском и возвращается 400 без внятной причины.
- **`claude`** — через `supabase/functions/translate` (Deno + официальный SDK,
  `claude-opus-5`, `effort: low`). Ключ в секретах функции: сайт статический на Pages,
  ключ в браузере утечёт в первый же день. Развернута функция или нет, снаружи не видно —
  узнаём по первому вызову и при 404/503 гасим пункт меню на сессию (`mtClaudeDown`).
- **`openrouter`** — ключ **читателя**, вставленный в настройках («⚙ → Перевод через ИИ»)
  и лежащий в localStorage под `chitalka:orkey`. CORS у OpenRouter открыт → зовём прямо
  из браузера, сервер для этого пути не нужен вовсе. Платит владелец ключа, модель
  выбирает он же (`settings.mtModel`).
  - ⚠️ **Ключ хранится вне `settings`** — намеренно: `settings` уходят в файл резервной
    копии (экспорт), а секрету там не место. Значит и на другом устройстве его надо
    вставлять заново — это цена того, что он никуда не уезжает.
  - ⚠️ **Общий ключ так класть нельзя, свой — можно.** Разница не техническая, а чей это
    кошелёк: ключ в localStorage виден любому скрипту на странице. Отсюда же два разных
    ИИ-пути (`claude` через функцию — общий ключ; `openrouter` — личный), и это не
    дублирование, а два разных плательщика.
  - **Список моделей тянется живым** (`mtModels()` → `GET /api/v1/models`, без ключа) и
    подставляется в `<datalist>`; захардкоженный перечень протух бы к следующему релизу
    моделей. Отфильтрованы `:batch` (отложенный ответ — в чат-эндпоинте зависнет) и
    модели, не умеющие выдавать текст. Желаемые модели (`MT_MODEL_PREF` в `app.js`) —
    **списком точных id, не регуляркой**: регулярка «любой claude-opus» в алфавитном
    каталоге выбирает `claude-opus-4` ($15/$75) вместо свежего и втрое дешёвого.
    Отсутствующие в каталоге id молча пропускаются.
  - ⚠️ **Заголовок `X-Title` — только латиницей.** Значение заголовка это ByteString;
    кириллица роняет сам `fetch` (TypeError) ещё до отправки, и перевод жалуется на
    «нет сети». Проверено — так и было в первой версии.
- Переводы кэшируются в localStorage (`chitalka:mt:`), 300 записей; **модель входит в
  ключ кэша** — один фрагмент у разных моделей переводится по-разному.
### Режим перевода: своё выделение вместо системного

⚠️ **Обычное выделение текста для перевода на телефоне не годится, и это не чинится.**
Браузер сам рисует над выделением «Копировать / Поиск / Поделиться», меню перекрывает
нашу панель, и до кнопки перевода не дотянуться. Подвинуть или убрать системное меню
нельзя. Отсюда режим перевода (кнопка **⇄** в верхней панели, `setMtMode`):

- в режиме текст получает `user-select: none` — браузеру нечего выделять, **меню не
  появляется вовсе**. Не «чинить» это возвращением обычного выделения: оно и было причиной.
- выделение своё: тап по слову (`caretOffset` → `wordAt`), тап по второму слову тянет
  фразу между ними, кнопка «Весь абзац» берёт член пары целиком. Границы слов —
  `Intl.Segmenter` (знает арабскую вязь с огласовками; регулярка — запасной путь);
  попадание в пробел или запятую берёт ближайшее слово, иначе аккуратный тап часто
  не давал бы ничего.
- подкраска — `paintParts`, а НЕ `highlightRange`: тот зовёт `surroundContents` на весь
  диапазон и молча ничего не красит, стоит фразе пересечь `<b>` или ссылку на сноску.
  Невидимое выделение хуже, чем никакого.
- панель прижата к низу (`#mtsel-bar`, z-index 38 — под оверлеями, над нижней панелью
  глав). Пока карточка встроена под абзац, панель остаётся на месте — можно сразу
  выделять следующий фрагмент; прячется только если карточка показана поверх текста.
- **двойной тап по абзацу = весь абзац**: кнопка «Весь абзац» есть, но тянуться к ней
  ради самого частого действия неудобно (так же сделано в Smart Book — там абзац
  переводится вообще без выделения).
- смена главы и уход в библиотеку сбрасывают выделение — его узлов больше нет в DOM.

### Промпты перевода

Промпт — **своя команда ИИ**. Две формы, различает их слот `{текст}` (`{фрагмент}`,
`{text}`, `{selection}` — то же самое):
- **без слота** — просьба ПОВЕРХ перевода: сначала перевод, потом разбор;
- **со слотом** — своя команда ЦЕЛИКОМ, выделенное подставляется в неё, и перевода
  как такового не будет. Тогда переводческий системный промпт заменяется на общий
  (`mtMessages`): требование «верни только перевод» прямо противоречило бы команде.
  Осторожность с религиозным текстом остаётся в обеих формах — она про цену ошибки,
  а не про формат ответа. ⚠️ Развилка продублирована в `translate.js` и в Edge
  Function; они обязаны совпадать. `MT_SLOT` глобальная, поэтому перед `.test()`
  сбрасываем `lastIndex` — иначе каждый второй вызов на той же строке даёт false.
Встроенные — `MT_PROMPTS_BUILTIN` в `app.js`, свои — `settings.mtPrompts` (не секрет,
поэтому в настройках и в резервной копии). Выбор — чипсами и в панели режима, и в
карточке результата: переспросить иначе, не выделяя заново.

- ⚠️ **`plain` особый: пустой текст.** Пока просьбы нет, в системный промпт возвращается
  строка «только перевод, без пояснений»; вместе с просьбой разобрать термины она —
  прямое противоречие, и модель выполняет случайную половину. Логика продублирована
  в `translate.js` и в Edge Function — они обязаны совпадать.
- Промпт понимают только ИИ-движки. MyMemory — словарь, класть просьбу некуда, поэтому
  при непустом промпте движок переключается сам (`mtProviderForPrompt`), а если ИИ не
  настроен — говорим прямо. Молча отдать словарный перевод на просьбу «разбери
  грамматику» было бы обманом.
- Промпт входит в ключ кэша: тот же фрагмент с другой просьбой — другой ответ.

- ⚠️ **Отдельного меню выбора провайдера нет и не заводить.** Оно висело под панелью
  выделения — ровно там, где браузер рисует своё «Копировать / Поиск», и системное
  перекрывало наше. Перевод запускается сразу выбранным движком (`settings.mtProvider`),
  а переключатель живёт внутри карточки результата, прижатой к низу экрана. Выделение
  снимается первым делом — это заодно закрывает системное меню.
- В клиенте Supabase для этого добавлены `functionUrl` / `functionHeaders`.

Включить ИИ-перевод есть два независимых способа:
- **Свой ключ (просто, ничего не разворачивать):** настройки → «⇄ Перевод через ИИ» →
  вставить ключ OpenRouter, выбрать модель. Работает только у того, кто вставил ключ.
- **Общий ключ для всех (нужен сервер):** `supabase functions deploy translate` +
  `supabase secrets set ANTHROPIC_API_KEY=…`. ⚠️ Функция зовётся с anon-ключом, то есть
  любой, прочитав исходники, может жечь кредиты — прежде чем включать, закрыть вызов
  (`verify_jwt` / лимит по IP / потолок трат на ключе).

Без обоих работает только бесплатный MyMemory.

## Подстрочник — перевод под словом (2026-08-20)

Под каждым словом изучаемого языка — короткая приглушённая подпись. Механика —
`gloss.js`, формат — **SPEC 3.4c**, генератор — `tools/gloss-book.js`, кнопка 🔤.

**Подписи поставляются ВМЕСТЕ С КНИГОЙ**: `books/<id>/gloss/<язык>/<глава>.md`,

двуязычная книга, где к сектору приложены ещё и пословные подписи.

⚠️ **Встроенного словаря лемм НЕТ и заводить его не надо.** Он был написан и удалён
в тот же день. Словарь даёт перевод леммы, слепой к предложению, и на омонимах врёт:
`left` подписывался «оставлять» посреди *left hand*, `saw` — «видеть» вместо пилы,
`light` — «свет» вместо «лёгкий». Проверено на живом словаре из 882 слов.

⚠️ **Запрос к модели ДВУХТАКТНЫЙ, и это не украшение.** Такт 1 — связный буквальный
перевод сектора; такт 2 — раскладка ЭТОГО перевода по словам оригинала. При пословном
проходе у модели нет причины поставить творительный падеж: она смотрит на слово в
списке, а не на фразу. С двумя тактами `pencil` сам собой получает «карандашом» и
«карандаш» в одном секторе. Рабочий перевод сохраняется в файл комментарием
`<!-- ru: … -->` — читателю он не показывается никогда, он нужен тому, кто выверяет:
иначе видно подписи, но не видно, откуда они взяты.

- ⚠️ **Нумерация слов — одна на три стороны.** `glossTokens` в `parser.js` считает
  слова генератору, валидатору и читалке. Своей нумерации не заводить: разойдись они
  на единицу — рой съедет по всему сектору, и подпись под чужим словом прочтётся как
  перевод. Считается по РАЗМЕЧЕННОМУ html, не по markdown.
- **Слово в записи — контрольная сумма.** Под номером N не то слово — подпись не
  ставится вовсе. Правка текста теряет отдельные подписи, а не сдвигает весь рой.
- **Плотность решается на ПОКАЗЕ.** В данных максимум: подписаны все слова, включая
  служебные и имена собственные. Показать меньше бесплатно, показать больше — только
  перегенерацией, а она платная. Читалка по умолчанию не рисует класс `f`.
- **Пустая подпись явная**: `->12` значит «смысл несёт слово 12». Отсутствие строки
  и намеренная пустота — разные вещи; первое неотличимо от потери.
- **`inline-grid`, не `inline-block`**: базовая линия берётся от первого ряда, то есть
  от слова. Хвостовая пунктуация втягивается в обёртку, иначе запятая отъезжает.
- **Порядок**: подстрочник кладётся ПОСЛЕДНИМ (после `applyMarks`) и снимается ПЕРЕД
  перекраской пометок. `highlightRange` при неудаче `surroundContents` падает в
  `paintParts` — это чинит и старый тихий баг с выделением поперёк сноски.

### Что показали прогоны через живые модели

Промпт проверен на grok, Sonnet и Haiku; арабский — на секторах из `tawfiq`.

- ⚠️ **Haiku не годится ни на арабском, ни на английском.** На арабском ду'а стала
  утверждением о прошлом («да утвердит нас Аллах» → «укрепил нас Бог»), а имя Аллаха —
  «Богом». На английском ломала сам формат: пустые подписи вместо стрелок, `→ 5`
  вместо `->5`, класс, приклеенный к слову (`4 af`), русское слово, разорванное надвое.
  **Арабское ядро генерируем Sonnet; Haiku не использовать.**
- **Устойчивость** (один сектор, Sonnet, три прогона): номера, слова и классы совпали
  19/19 во всех трёх — структура не ездит. Подписи совпали 16/19, расхождения
  синонимичные («разделения»/«разлуки»). Уровни — самое шаткое, 16/19.
  Отсюда: **перегенерировать только протухшее**, иначе диффы шумят, а выверка слетает.
- **Словарную форму нормализует КОД** (`glossNormalizeBase`), а не уговоры: на трёх
  прогонах модель дала и `توقع`, и `توقّع`. Снимаем краткие огласовки и сукун, шадду
  сохраняем (она различает породы). Артикль `ال` не трогаем механически — в `الله`
  это не артикль, и «нормализация» дала бы `له`.

### Хеш и выверка

- `h=…` на якоре — хеш **последовательности слов**, не html. Выделили слово жирным —
  html другой, а подписи верны; хеш от html гнал бы на перегенерацию на ровном месте,
  а правка `parser.js` обнулила бы его по всей библиотеке разом.
- `ok` на якоре — сектор выверен человеком. Перегенерация флаг снимает: проверяли не
  этот текст. **Непротухший сектор не трогается даже при повторной вклейке** — только
  с `--force`.
- Показ: пунктиром под каждой подписью не обойтись — пока не выверено ничего, это
  пунктир на всей странице. Гарантию даёт переключатель «только выверенное»
  (не рисует неподтверждённое), а пунктирная грань у сектора появляется только когда
  отбор включён — чтобы было видно, что подписи СКРЫТЫ, а не отсутствуют.

### Генератор `tools/gloss-book.js`

Конвертер формата не нужен — текст книги не меняется. Нужен генератор ДАННЫХ.

```bash
node tools/gloss-book.js books/_sample-en --lang en --prompt 01.md [--sector s005]
node tools/gloss-book.js books/_sample-en --lang en --apply 01.md < ответ.txt
ANTHROPIC_API_KEY=… node tools/gloss-book.js books/_sample-en --lang en --run [--force]
node tools/validate.js books/_sample-en
```

- Промпт живёт в `parser.js` (`glossPrompt`) рядом с нумерацией, от которой зависит;
  второй его потребитель — добор по требованию в читалке (метод 2, не сделан).
- ⚠️ Обращение к API — **голым `fetch`, без SDK**: в репозитории нет `package.json`.
  Появится — переписать на `@anthropic-ai/sdk`.
- Ключа в окружении нет; пробные прогоны шли через установленные CLI (`grok -p`,
  `gemini -p`, `codex exec`) и через слепых субагентов.

## Поиск, пометки и импорт (22.08.2026)

**Поиск ранжируется, а не сравнивает подстроку.** Было `norm.indexOf(q)`, поэтому
запрос из нескольких слов не находил место, где между ними номер сноски или
вводное слово. Теперь ищутся слова и оценивается кучность: точная фраза (×8) >
по порядку и рядом (×4) > рядом в любом порядке (×2) > все слова врозь (×1.5) >
большинство слов (×1); частота поднимает вес логарифмически. Сортировка по весу,
показываются 300 лучших из первых 2000 найденных. Слово запроса засчитывается и
как часть слова текста (так вело себя прежнее сравнение), но для
одно-двухбуквенных требуется точное совпадение. Порядок надбавок взят у
`البحث الإجمالي` Шамили. Функции — `оценить`, `поПорядку`, `вЛюбомПорядке` в `app.js`.

**Пометки сверяются со снимком.** Якорь (сектор + смещения) после переимпорта
может указывать на другой текст — раньше подкраска молча ложилась не туда.
`сверитьПометки()` вызывается ОДИН раз на отрисовку главы (не в `applyMarks`:
покрашиваемся часто, а поиск снимка перечитывает главу — на этом вкладка
подвисала). Снимок не сошёлся → ищем заново по главе → нашли точно →
перепривязываем (`moved`); не нашли → `orphan`, не красим, в списке вырезок
плашка «текст изменился». Перепривязка только по ТОЧНОМУ совпадению.

**Глава — свойство пары, а не приложения.** `data-chapter` на каждой паре;
данные (пометки, закладки, вырезки, позиция) пишут `chapterOf(el)`, а не
`chapterIndex`. Якоря ищутся через `pairAt(глава, сектор)`: `s003` есть в каждой
главе. Это первый шаг к непрерывному чтению; второй (якоря с главой) сделан
14.11.2026 под статьи — они читаются одной страницей (раздел «Книги и статьи»).
Подгрузка и выгрузка глав у КНИГ — по-прежнему в BACKLOG.

**`tools/doctor.js`** — аудит библиотеки целиком (реестр, поля под фасеты,
связность, тип записи и дата статьи, свежесть `counts`/`description`), в CI перед
выкладкой. Односторонняя глава — не поломка; неизвестный `kind` и нечитаемая дата — поломка.

**`tools/import-bok.js`** — одноязычные книги из старого формата Шамили (`.bok`).
Два шага: питон `~/projects/tools/shamela/import/bok2md.py` читает Access и кладёт
сырьё, Node пишет Контракт через `contract.js`. Второго писателя Контракта не
заводить. Первая книга оттуда — `books/tazkar/` («التذكار» аль-Куртуби, 72 главы).
